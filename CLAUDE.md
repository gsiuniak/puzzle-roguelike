## 2. Project Overview

**Project:** `gems` — Match-3 Puzzle Roguelike
**Stack:** Vanilla JavaScript (ES modules), HTML5 Canvas, Howler.js for audio
**Build:** No bundler is REQUIRED — the game runs raw by serving the project and opening [`src/index.html`](src/index.html) (native ES modules + relative asset paths, no build step). This is still the primary dev/serve flow. Root `package.json` sets `"type": "module"` so node tooling (`sim/` scripts/tests) can import the `src/js` ES modules directly.
**Optional Vite build (for distribution):** [`vite.config.js`](vite.config.js) adds an ADDITIVE build that does NOT change raw serving — `npm run build` → a minified, **PWA**-enabled `dist/` (installable on mobile/desktop; offline via a service worker), `npm run dev` (HMR), `npm run preview` (serve `dist/`). Key invariants: `root:'src'` (builds the same untouched `src/index.html`), `base:'./'` (works at a domain root AND a subpath like itch.io), game `assets/` are referenced by STRING path / runtime `fetch()` (not Vite imports) so they're copied to `dist/assets` VERBATIM (the `copyGameAssets` plugin) and every runtime path resolves identically; Vite's hashed output goes in a separate `bundle/` dir. PWA precaches only the JS/CSS/HTML shell and runtime-caches images/audio/fonts/json with **StaleWhileRevalidate** (serve cached instantly, re-fetch in the background so a changed/broken asset self-heals next visit — the game's assets live at STABLE, non-hashed URLs, so `CacheFirst` would pin a stale/broken copy; the SFX `.ogg` sprite + its `.json` offset map MUST share a strategy or they desync after a repack). Only `200`s are cached; the SW uses `cleanupOutdatedCaches`/`clientsClaim`/`skipWaiting` so a new deploy takes over promptly. cutscene `.mp4`s are intentionally not cached. **Install icons** = [`src/assets/icons/`](src/assets/icons/) `icon-192.jpg` / `icon-512.jpg` (192/512 square; the 512 is also the maskable + iOS `apple-touch-icon` linked from `index.html`). JPEG is manifest-valid; swap to PNG by editing the manifest `type`/`src`. [`index.html`](src/index.html) has a self-contained **Install button** (`#install-btn`) wired to `beforeinstallprompt` — it reveals only when the browser deems the app installable (HTTPS + manifest + icon + SW) and is a no-op on raw http serve / iOS Safari. Same `dist/` output also feeds Electron (desktop) / Capacitor (mobile store apps) if ever wanted.
**Entry:** [`src/index.html`](src/index.html) → [`src/js/main.js`](src/js/main.js)

### Scene Flow

```
LoadingScene  →  TitleScreen  →  CharacterSelectScene  →  MapScene  ⇄  BattleScene
(preload)              ↑                   (roam)  │    (combat)
                       │                           │        ↓
                       │              (boss only)  │  victory: RewardOverlay → MapScene
                       │            BossIntroScene─┘  defeat:  GameOverScene
                       └─────────(any input)─────────────────┘
```
On boot the game shows **LoadingScene** (a minimal dark/gold preload screen) FIRST
while assets stream in, then fades to TitleScreen once `AssetManager.progress`
reaches 1. The game loop starts immediately on LoadingScene — asset loading is
NOT awaited before boot (see [`main.js`](src/js/main.js) `init`).
On **victory** the post-battle RewardOverlay drives the return to MapScene. On
**defeat** the player is routed to the full-screen **GameOverScene**; any input
there returns to CharacterSelectScene to start a fresh run. When an enemy def
carries an `introVideo` (today only Lord Malakor), MapScene routes through
**BossIntroScene** — a full-canvas no-audio video cutscene that starts the boss
music — before cross-fading into the BattleScene.

## 3. Project Rules

**Violate these only when explicitly instructed.**

1. **Do not rebuild systems unless asked.** Prefer small, focused changes.
2. **Keep UI data-driven.** CharacterPane reads from data objects; never hardcode values.
3. **Keep rendering separate from game logic.** BoardModel/MatchResolver never touch canvas. Visuals live in BattleScene/BoardPlaceholder/MapRenderer.
4. **Skills use `effects: []` array only.** Each effect has an `effectType` string. See [`SKILL_EFFECT_TYPES`](src/js/game/MatchResolver.js:23).
5. **Skill sound is attached to the skill definition** (`skill.sound`), not individual effects.
6. **Tile destruction rewards use centralized logic** — [`resolveDestroyedTileRewards()`](src/js/game/MatchResolver.js:199) in MatchResolver.
7. **Extra turns are non-cumulative retain-turn flags.** Set `_extraTurnEarned`; don't stack.
8. **Map generation is separate from map rendering.** MapGenerator creates the graph; MapRenderer/MapView draw it.
9. **Old/reference directories are read-only** unless explicitly instructed. See §8.
10. **Enemy data uses the same structure as character data** (hp, mana, skills, portrait).
11. **All asset keys are registered in [`main.js` ASSET_MAP](src/js/main.js:35).** Adding a new sprite requires adding it there.
12. **New characters require:** (a) per-character file in [`src/js/data/characters/`](src/js/data/characters/) with `baseStats` structure, registered in [`characters/index.js`](src/js/data/characters/index.js), (b) entry in [`characterSelectDefinitions.js`](src/js/data/characterSelectDefinitions.js), (c) asset registration in [`main.js` ASSET_MAP](src/js/main.js:35).
13. **Character definitions are immutable.** Never mutate `baseStats` during gameplay. Run modifiers go in `runState.statModifiers` via [`playerStats.applyRunModifier()`](src/js/data/playerStats.js).
14. **All stat math goes through [`playerStats.js`](src/js/data/playerStats.js).** Use `getEffectivePlayerStats()` to resolve stats, `createPlayerBattleState()` for battle init, `syncBattleResultsToRunState()` for persistence. Never scatter `base + modifier` math outside this module.
15. **Rewards modify runState.statModifiers, never baseStats.** Use `applyRunModifier(runState, 'startingMana.purple', 2)` pattern.
16. **Skills and relics are referenced by ID, not embedded.** Character/enemy definitions list `skills: ['bash']` / `relics: ['family_crest']`. Full data lives in [`skillCatalog.js`](src/js/data/skills/skillCatalog.js) and the relic catalogs. **Relics are drawn from two separate pools:** players use [`relicCatalog.js`](src/js/data/relics/relicCatalog.js) (`resolveRelicIds`), enemies use the enemy-only [`enemyRelicCatalog.js`](src/js/data/relics/enemyRelicCatalog.js) (`resolveEnemyRelicIds`) — the two pools never mix, which is how enemy relics stay out of the player reward pool. Resolved shapes are identical, so the BattleController/PassiveSystem treat them the same. IDs are resolved into objects at battle-state creation (`createPlayerBattleState` for players, `MapScene._transitionToBattle` for enemies). **One exception:** WOVEN skills (Skill Weave rewards) are synthesized at runtime and exist in no catalog, so they live as FULL skill objects on `runState.skills` and are appended to the resolved catalog skills by `createPlayerBattleState` (deep-cloned per battle).
17. **Passive abilities are data-driven via PassiveSystem.** Never write `if (relic.id === 'X')` checks in battle logic. BattleController dispatches trigger events (see [`TriggerTypes.js`](src/js/systems/TriggerTypes.js)); [`PassiveSystem`](src/js/systems/PassiveSystem.js) routes them to matching relic effects through [`EffectResolver`](src/js/systems/EffectResolver.js).
18. **Atomic effects (damage, armor, heal, gain_mana, drain_mana, extra_turn, reduce_damage) live in [`EffectResolver`](src/js/systems/EffectResolver.js)** and are shared between skill resolution and passive resolution. Board-touching effects (create_tiles, destroy_tiles, destroy_tiles_row, destroy_tiles_radius) stay in BattleController because they drive the cascade phase machine. Passive board effects flow through `PassiveSystem.onBoardEffect` — `BattleController._handlePassiveBoardEffect` matches on `effect.effectType` and mutates the in-flight cascade's `_analysis` (positions/mana/skullDamage) so the existing SHOW_MATCH → REMOVE flow handles destruction + rewards.

19. **All damage funnels through [`BattleController._applyDamage(target, amount)`](src/js/game/BattleController.js).** It dispatches `onIncomingDamage` (mutable `amount` payload) before delegating to `MatchResolver.applyDamage`, so defensive passives like Evil Eye (`reduce_damage` effect) can mitigate damage uniformly across skill DAMAGE, cascade skull damage, destroyed-tile skull damage, and passive damage effects. The resolver injected into PassiveSystem is a thin wrapper whose `applyDamage` routes back through `_applyDamage`, so passive-applied damage receives the same pre-mitigation pass. Never call `this.resolver.applyDamage(...)` directly from BattleController.

```

```

### 4.8 Composited Spell Icons

Runtime-assembled circular icons for synthesized (woven) spells — the icon is built by **layering authored spritesheet art with blend modes** (NOT procedural drawing). Layer stack: colored base mana-orb (bottom) → optional minor effect (MULTIPLY) → major effect (COLOR-DODGE) → `icon_border_2` cap (normal). The blend modes make the white effect sprites feel energized by the base color rather than pasted on. Two separable concerns + a cache layer:

| File | Exports | Responsibility |
|------|---------|----------------|
| [`src/js/icons/spellIconRecipe.js`](src/js/icons/spellIconRecipe.js) | `resolveIconPlan`, `hashString` | **Layer SELECTION (pure logic, no canvas).** `resolveIconPlan(tags, cost, spellId, assetManager?)` → `{ baseKey, minorKey, majorKey, borderKey, color, majorTag, minorTag, signature }`. **BASE** = the spell's dominant mana color from `cost` (highest-amount color; ties broken by the spell's first element tag; else neutral). **EFFECTS** = effect-bearing tags (actions/statuses/shapes/modifiers — elements only color the base) ranked by `EFFECT_TAG_PRIORITY`: top = MAJOR (the color-dodged subject), next distinct = MINOR (multiplied). A verb-less bag falls back to `DEFAULT_EFFECT_TAG` ('damage'). **BORDER** = `icon_border_2`. **Variants** (`<color>_base_<n>` / `foreground_<tag>_<n>`) are auto-discovered by probing the AssetManager (`isLoaded`), picked deterministically per spell; missing sprites degrade gracefully (skip / neutral / bare-prefix). `signature` = the resolved sprite keys (the cache key; two spells with identical layers share one icon). Unit tests: `node sim/test-spell-icon-recipe.mjs`. |

### Stat Architecture Flow (NEW)
```
Character Definition (immutable template)
  data/characters/<name>.js: { id, baseStats: { maxHp, startingMana, startingArmor, startingAttack }, skills, relics, ... }
        +
Run State (persistent progression)
  runState.js: { characterId, currentHp, statModifiers: { maxHp, startingMana: {...}, ... }, relics, ... }
        =
Effective Stats (computed each battle via playerStats.js)
  getEffectivePlayerStats(characterDef, runState)
        =
Battle State (fresh each battle via playerStats.js)
  createPlayerBattleState(characterDef, runState)
  ↳ HP starts at full effective maxHp — current HP does NOT persist between fights
        |
  [Battle plays out, playerState mutated by BattleController]
        |
  syncBattleResultsToRunState(runState, playerState) — writes runState.currentHp,
  but it is no longer used to seed battle HP (kept for save/UI bookkeeping)
```

**Key rules:**
- Character definitions are **immutable** — never mutate `baseStats`
- Run modifiers (`statModifiers`) are **additive** — rewards/relics/upgrades modify these, not base stats
- Effective stats are resolved through **centralized helpers** only — no scattered `base + modifier` math
- Battle state is **temporary** — created fresh each battle; mana/armor/attack reset from effective stats
- HP does **not** persist between fights — every battle starts at full effective `maxHp`. `currentHp` is still written back by `syncBattleResultsToRunState` but is not read to seed battle HP. Mana/armor/attack also reset each battle.
- Rewards use `applyRunModifier(runState, statPath, amount)` to modify run statModifiers

### Skill Resolution Flow
```
Player clicks skill → CharacterPane.onSkillClick → BattleController.tryPlayerSkill(skill)

1. If board_tile targeting: enter TARGETING state (seeds a default center target)
   → DESKTOP: hover previews the area; CLICK a tile → tryTargetTile (instant cast). Centered Cancel button only.
   → TOUCH: tap/drag a tile: setTargetHover → preview area (does NOT cast); Cast button / Enter → confirmTarget → tryTargetTile
   → both: Cancel button / ESC / right-click: cancelTargeting

2. If instant: _spendCost → _setSkillSound → for each effect:
   → DAMAGE: applyDamage() → shake + log
   → ARMOR: src.armor += amount
   → HEAL: src.hp = min(maxHp, hp + amount)
   → CREATE_TILES: convert random tiles → check matches → beginResolving
   → EXTRA_TURN: set _extraTurnEarned flag (non-cumulative)
   → DESTROY_TILES: _executeDestroyTiles → resolveDestroyedTileRewards → beginResolving

3. For targeted skills (tryTargetTile after tile click):
   _spendCost → _setSkillSound → compute area, then dispatch per effect:
   → DESTROY_TILES / DESTROY_TILES_ROW: _executeDestroyTiles(area)
   → CONVERT_TILE: _executeConvertTile(area, type) → match check → beginResolving
   → other effects: standard _resolveEffect (damage/armor/etc.)
   If no effect entered RESOLVING, the turn ends inline (mirrors tryPlayerSkill).
```

## 7. Current Known Architecture Decisions

1. **Skills use `effects: []` array only.** Each effect is `{ effectType, damage?, armor?, heal?, createTiles? }`. No other skill resolution mechanism exists.
2. **Skill sound is on the skill definition** (`.sound` field), not on individual effects. Played once per skill resolution via `_pendingSkillSound`.
3. **Tile destruction rewards use centralized [`resolveDestroyedTileRewards()`](src/js/game/MatchResolver.js:199)** in MatchResolver, called from both match cascades and skill-based destruction.
4. **Extra turns are non-cumulative retain-turn flags.** `_extraTurnEarned` is a boolean. The scene reads `pendingExtraTurn` and `extraTurnTriggerPos` (one-shot cleared via getState). **Ordering gotcha:** in a multi-effect skill, an `extra_turn` effect must come AFTER any `create_tiles` effect — `create_tiles`' `_beginResolving` resets `_extraTurnEarned` to false, so it must be (re)set afterward to survive the cascade and be honored in `_finishResolving`. (The `destroy_tiles` path preserves the flag; `create_tiles` does not.) **Enemy instant-skill extra turns must reset the enemy fire gate.** The enemy turn is timer-driven via `_enemyFired`/`_enemyTimer`; an INSTANT enemy skill (no cascade) that grants extra_turn (e.g. Cyclops' Smash) routes through [`_beginEnemyExtraTurn()`](src/js/game/BattleController.js), which re-arms `_enemyFired=false`/`_enemyTimer=0` and stays in ENEMY_TURN. Just setting `pendingExtraTurn` (the player's input-driven path) would leave `_enemyFired=true` and **freeze the battle** — the enemy would never act again. **Fresh turns clear stale flags.** Legitimate extra turns continue via `_finishResolving` / `_beginEnemyExtraTurn`, which set PLAYER_TURN/ENEMY_TURN directly and BYPASS `_completeTurnIntro` — so when a normal `TURN_INTRO` completes, any still-set `_extraTurnEarned`/`pendingExtraTurn` is STALE and `_completeTurnIntro` clears both. This enforces the invariant "a fresh (non-extra) turn never inherits a pending extra turn" and prevents a leaked flag from silently swallowing the next turn (the "cast a spell → turn just doesn't pass, with no extra-turn indication" bug; a pure instant skill has no way to set the flag mid-turn, so a stuck flag can only be stale).
5. **CharacterPane must be data-driven.** `updateFromState(combatantState)` reads HP, mana, armor, block. No hardcoded character-specific logic.
6. **Map generation is separate from map rendering.** MapGenerator creates immutable MapGraph; MapRenderer/MapView draw it; MapTraversalController manages state mutations.
7. **Local-lane constraint:** Connections between consecutive depths may only move vertically by at most 1 lane (|source.lane − target.lane| ≤ 1). Node counts are smoothed (±1 between depths) to guarantee valid targets exist. Edge validation enforces this at generation time. The start node is centered at `START_LANE` so its ±1 fan-out reaches 3 lanes (depth 1 = 3 nodes). The two guaranteed elites are placed by `_placeReachableElites` *after* wiring/validation (the late elite is picked from the early elite's reachable descendants, so a route through both always exists without a fixed spine). MapRenderer applies a small deterministic per-node jitter (`_idJitter`) so positions aren't a rigid grid.
8. **MapView is shared** between MapScene (fullscreen) and BattleScene (overlay via 'm' key).
9. **BattleScene is created on demand** (registered lazily by MapScene), not at boot.
10. **MapScene is a singleton** — graph, renderer, traversal, `_runState`, and `_characterDef` all survive scene switches.
11. **Enemy HP AND attack scale per floor in MapScene** ([`_transitionToBattle`](src/js/scenes/MapScene.js)): each enemy's `maxHp`/`attack` in the data files is a **floor-1-equivalent baseline**. **HP** is multiplied at spawn by `ENEMY_HP_FLOOR_MULT[node.depth]` (player-DPT-ratio curve, bumped slightly so fights run a touch longer). **Attack** gets an ADDITIVE per-floor step bonus `ENEMY_ATTACK_FLOOR_BONUS[node.depth]` (≈ +1 every 2 floors, top +4 — steepened 2026-06-23 so enemy damage outruns the now-deterministic player HP growth; see [`docs/balance-combat-math.md`](docs/balance-combat-math.md) §7.1) on top of the authored base — attack is the lethality knob (it drives skull-match damage AND now enemy SKILLS, which carry `scaling`), so it ramps as small additive steps (preserving per-enemy identity) rather than a multiplier. A per-enemy **`attackScale`** (default 1) scales that floor bonus for designed exceptions (0 = opt out). **Tiering is by base value + role** (minions authored ~12-18, elites ~24-28) and floor-gating. Sim-derived budgets live in `sim/`; see [`docs/balance-findings.md`](docs/balance-findings.md). **(Enemy skills scale too — see decision #34/#35: enemy damage/armor skills carry `scaling: { attack }`, so they grow with the floor-scaled attack.)**
12. **Music transitions are state-driven** in BattleScene: battle_theme on PLAYER/ENEMY_TURN, stopped on GAME_OVER.
13. **All one-shot visual/SFX flags** are read-and-cleared in `BattleController.getState()` to prevent double-firing.
14. **Player stat architecture uses three-layer separation** (NEW):
    - **Layer 1 — Character definitions** (per-file in [`data/characters/`](src/js/data/characters/)): Immutable `baseStats` templates. Never mutated.
    - **Layer 2 — Run state** ([`runState.js`](src/js/data/runState.js)): Persistent `statModifiers` that accumulate from rewards/relics/upgrades. `currentHp` is tracked but does NOT seed battle HP — each fight starts at full `maxHp`.
    - **Layer 3 — Battle state**: Fresh instance created each battle via [`createPlayerBattleState()`](src/js/data/playerStats.js). Mana/armor/attack reset from effective stats each battle.
15. **Stat resolution is centralized** in [`playerStats.js`](src/js/data/playerStats.js). `getEffectivePlayerStats()` is the single source for computing baseStats + statModifiers. No scattered math elsewhere.
16. **Rewards modify run modifiers, not base stats.** Use `applyRunModifier(runState, statPath, amount)`. Example: `applyRunModifier(runState, 'startingMana.purple', 2)`.
17. **HP resets to full each battle.** `createPlayerBattleState` seeds `hp` from effective `maxHp`, so current HP does NOT carry between fights. `syncBattleResultsToRunState()` still writes `currentHp` to run state (bookkeeping) but it isn't used to seed battle HP. Battle mana/armor/attack/temporary effects also do NOT persist.
18. **Canvas uses DPR-aware rendering** — all layout is in CSS pixels; context is pre-scaled.
19. **Post-battle flow: Level Up → Reward → map** — GAME_OVER does NOT immediately return to MapScene. On VICTORY, BattleScene first shows the [`LevelUpOverlay`](src/js/ui/LevelUpOverlay.js) (mandatory attribute pick); its `onDismiss` then opens the [`RewardOverlay`](src/js/ui/RewardOverlay.js); the reward overlay's `onDismiss` → `_returnToMap`. Both render over the still-visible BattleScene with a dark backdrop. ESC dismisses the reward overlay (not the level-up one). See decision #36.
20. **Enemy AI overrides are dispatch-based, not conditional.** Custom AI is registered in [`enemyAiOverrides.js`](src/js/game/enemyAiOverrides.js) as handler functions keyed by `aiBehavior`. [`customEnemyAi.js`](src/js/game/customEnemyAi.js) orchestrates: try custom → fallback to standard `EnemyAI`. Enemy definitions link via optional `aiBehavior` field.
21. **Skills and relics are id-referenced + catalog-resolved.** Character/enemy definitions store `skills: string[]` and `relics: string[]`. Resolution happens once at battle-state creation: [`createPlayerBattleState`](src/js/data/playerStats.js) for players, [`MapScene._transitionToBattle`](src/js/scenes/MapScene.js) for enemies (calls `resolveSkillIds` / `resolveRelicIds`). [`BattleController._cloneState`](src/js/game/BattleController.js) deep-clones the resolved relics + effect arrays so per-battle mutation cannot leak back to catalogs or runState; it is FIELD-EXPLICIT, so any new battle-state field must be added there or it silently drops (this bit `allSkills` once — the loadout modal's pool — turning unequip into a trash can). Exception: woven skills are catalog-less full objects on `runState.skills`, deep-cloned into the battle state by `createPlayerBattleState` (see rule #16).
22. **Passive abilities are data-driven via PassiveSystem dispatch, not conditionals.** Battle code emits trigger events via `this.passives.dispatch(triggerName, payload)`. [`PassiveSystem`](src/js/systems/PassiveSystem.js) iterates the affected side's relics, matches by `effect.trigger`, and resolves via `applyEffect`. Adding a relic requires no code changes outside [`relicCatalog.js`](src/js/data/relics/relicCatalog.js). Recursion guard is intentionally absent (today's relics don't recurse — add depth limit when needed).
23. **Trigger dispatch points in BattleController:**
    - `onTileMatch` / `onTileMatchType` / `onMatch4Plus` — fired from `_enterShowMatch` (every cascade step)
    - `onTurnStart` — fired from `_completeTurnIntro` (after state is set to PLAYER_TURN/ENEMY_TURN)
    - `onTurnEnd` — fired from `_endTurn` (before transitioning to TURN_INTRO)
    - `onTakeDamage` / `onDealDamage` — fired by `_dispatchDamageEvent` after every `applyDamage` call that lands `actualDamage > 0` (skill DAMAGE, skull damage in `_doRemove`, skull damage in `_executeDestroyTiles`). **Passive-applied damage** routed through `EffectResolver`'s `damage` case (e.g. Briarthorn's onTurnStart hit, the onGainMana reactor relics) also dispatches these events: EffectResolver's `onDamage` hook now carries `caster`/`target` refs, and BattleController's PassiveSystem `onDamage` callback calls `_dispatchDamageEvent` so defensive reactors like Family Crest (gain mana when damaged) fire for EVERY instance of damage regardless of source. Damage-triggered passives reached this way (echo, Deathbringer) carry their own reentrancy / once-per-action guards, so it can't loop.
24. **Static-modifier relics bypass event dispatch.** Persistent passives (Group A spawn-rate, Group B mana-gain, Funerary Bell skull-damage, Claymore attack) are NOT event reactions, so they don't flow through PassiveSystem/EffectResolver. They use `trigger: 'onBattleStart'` and one of the static effect types (`modify_stat`, `modify_spawn_rate`, `modify_mana_gain`, `modify_skull_damage`). [`BattleController._initStaticModifiers()`](src/js/game/BattleController.js) scans both sides' relics ONCE at construction (before `board.initialize()`), dispatching by `effectType` (never by relic id):
    - `modify_stat` → adds to the combatant stat (e.g. `attack += 3`).
    - `modify_spawn_rate` → accumulates board-global percentage-point boosts, applied via [`BoardModel.setSpawnRateBoosts()`](src/js/game/BoardModel.js). `getEffectiveWeights()` raises each boosted tile to `base% + boost` and redistributes the remaining probability across the other tiles in proportion to their base rates (skull absorbs the remainder), so the boosted tile lands at exactly base+boost and the rest keep their ratios.
    - `modify_mana_gain` / `modify_skull_damage` → stored per-combatant as `_manaGainBonus` / `_skullDamageBonus`, applied in [`BattleController._applyMatchBonuses()`](src/js/game/BattleController.js) which augments each cascade step's analysis (in `_enterShowMatch`, before passive dispatch & reward granting).
25. **Turn-start passive cascades resume the turn, they don't consume it.** A turn-start board passive (today only Chokeweed Sap's `convert_random_tiles`) can line up a match. When it does, `_applyPassiveConvertRandomTiles` sets `_resumeTurnAfterResolve = true` and calls `_beginResolving(activeSide, …)` so the cascade fully resolves (mana/skull rewards go to the active side). `_finishResolving` then sees the flag and, instead of `_endTurn` / extra-turn routing, restores the active side's turn state (re-arming `_enemyFired`/`_enemyTimer` for the enemy) so the side still takes its normal action (e.g. Chokeweed casts Encroach right after). The flag also **suppresses the extra-turn grant + "Extra Turn" visual** in `_enterShowMatch`/`_finishResolving` (a turn-start match is setup, not the side's move, so a 4+ must not double the turn). onTurnStart is NOT re-dispatched on resume (it already fired before the cascade). The cascade only kicks off when `state` is `PLAYER_TURN`/`ENEMY_TURN` (turn-start), so a future mid-cascade trigger can't clobber an in-flight resolution.

26. **Turn-scoped debuffs (Silence, Exsanguinate) live on the combatant state and tick at the END of the debuffed side's own turn.** Soul Burn's `silence` sets `state._silencedTurns`; Exsanguinate's `set_attack` stores `state._attackOverride = { value, turns, savedAttack }` and pins `state.attack = value`. Both are applied to the OPPONENT by the caster's skill, so they're applied during one side's turn and must cover the OTHER side's next turn. [`BattleController._endTurn(side)`](src/js/game/BattleController.js) calls `_tickTurnDebuffs(side)` which decrements only THAT side's counters — so a debuff applied during the opponent's turn always lasts exactly through the affected side's next turn, then expires. **Silence** is enforced in `tryPlayerSkill` (`_isSilenced` early-returns, blocking skill casts; swaps still allowed); the visual indicator is intentionally not implemented yet. **Attack override** freezes the dynamic-attack recompute (`_recomputeDynamicAttack` early-returns while `_attackOverride` is set) and is re-pinned every frame in `update()` via `_enforceAttackOverride` (so a relic's mid-turn `gain_attack` can't break the "attack = N this turn" guarantee); on expiry `_tickTurnDebuffs` restores `savedAttack` and the recompute resumes, reconciling against current mana. Limitation (documented, rare): attack changes a player relic would make DURING an exsanguinated turn are suppressed and do not carry over. Both fields are runtime-only (not in catalogs), so a fresh battle state starts clean.

31. **The "Weave a Power" skill reward is a layered-RNG tag draft + a synthesis step — all randomness/data lives outside the scene.** [`SkillWeaveScene`](src/js/scenes/SkillWeaveScene.js) is a full-canvas scene that replaces the relic-style "pick 1 of 3 finished options" reward for **skills** with a variable-length keyword draft, then synthesizes the chosen "bag" of tags into a skill. It is fully decoupled across three data modules:
    - **RNG config** ([`weaveConfig.js`](src/js/data/weaveConfig.js)) owns every tunable table (tag-rarity weights, rounds-per-weave, tags-per-round, hidden per-tag value tables). All are **relative weights** normalized at pick time, so any single number tweaks in isolation (a table summing to 110, like the rounds weights, behaves fine). The scene rolls its shape via `_rollWeavePlan` → `{rounds, tagCounts}`.
    - **Catalog/draw** ([`skillWeaveTags.js`](src/js/data/skillWeaveTags.js)) owns the id-keyed tag catalog (each tag has a `rarity` + `category`) and `drawTagsForRound({roundIndex, chosen, count})`: a **rarity-weighted draw from one global pool**, no repeats, with a soft guarantee that round 0 includes ≥1 ACTION tag (so every bag has a verb). The old positional `[action, element, shape]` grammar (`ACTION_RULES`/`getValidTagsForStep`) is **gone** — validity is no longer enforced at draft time; the synthesizer makes sense of whatever bag results. Extend by adding a catalog entry (no scene change).
    - **Synthesis** ([`skillSynthesizer.js`](src/js/data/skillSynthesizer.js)) — `synthesize(recipe)` is the future "bag → real skill" engine; today a **STUB** that groups tags by category + rolls hidden values and emits no real skill. The deeper rules the user wants (special combos, "not every tag is used", premade-spell overrides) attach here, not in the scene.
    - **Draft state** is a `_recipe` (committed tag ids) + a `_steps` stack of `{options, picked?}` per step (`picked` = the committed option index, used so Back can fly the tag back to the right plaque). **Clicking a tag commits it immediately** (`_pickOption` pushes onto `_recipe` + builds the next step); **Back** pops `_recipe` and truncates `_steps` to `_recipe.length + 1`, restoring the previous step's exact options (never discarded). **Confirm** is gated on `_complete` (recipe full) and is the sole "resolve into a skill" action — there is no per-tag selection state; hover alone provides the grow+glow affordance.
    - **Animation layer** (`_anim`, advanced in `update`→`_advanceAnim`; input is locked while non-null via `_animBusy`). The draft model is mutated UP-FRONT by `_pickOption`/`_back` (so the slot + next-step data the animation reads already exist), then a purely-visual animation plays: **intro** (tags fan/grow out from a central focal point — the centroid of their rest rects — to position, staggered; on enter + after every commit/back), **commit** (clicked tag flies + pops into its recipe slot while the unpicked tags fade out → then the next step's intro), **back** (two phases: the current step's tags collapse back to the focal point reverse-intro, then the popped recipe tag flies out of its slot back to its plaque while the previous step's siblings fade in). All option drawing routes through `_drawOptionTransformed` (scale-about-center + reposition + alpha); the travelling tag is drawn on top of the recipe in `_renderFlyingTag`; slot content during animations is overridden in `_renderRecipe` (suppress the static tag for the slot being flown into/out of). Button visual-enabled deliberately ignores `_animBusy` so they don't flicker dim mid-animation. Timings/feel are all top-of-file constants (`INTRO_*`, `COMMIT_*`, `BACK_*`, `FLY_POP`).
    - **Variable layout.** The recipe holds 2–4 slots (= rounds) that **shrink to fit** the rolled count inside a height-budgeted container (`_recipeRect` caps height at `RECIPE_MAX_H` so the wider container art can't collide with the buttons; a **4-slot recipe swaps to the wider `ui_skill_weave_container_wide` art** via `_recipeContainerKey`); options arrange as 2/3-up fans or a 4-up grid (`_optionAnchors`, narrower plaques at 4 via `OPTION_W_BY_COUNT`). Option plaque art is **rarity-suffixed** (`_optionAssetForTag` → `ui_skill_weave_option_container_<rarity>`, common = base) with a rarity-tinted hover glow.
    - **Entry/exit mirrors the battle contract.** MapScene routes the `training` node via `_transitionToSkillWeave(node)` (serializes traversal into `_savedTraversalState`, `configure({onComplete, returnScene})`, `fadeToScene`). `onComplete` (payload `{recipe, synthesis}`) calls the SAME `_handleBattleComplete({result, nodeId})` battle uses, so on return `MapScene.onEnter` completes the node + reveals the next depth identically.
    - **The reward is REAL:** `_finishWeave()` calls `synthesize()` (the rule engine — see the skillSynthesizer row in §4.7) which emits a full castable skill (effects + hidden-rolled magnitudes + a CONTINUOUS power-scaled mana cost SPLIT across the woven colors + generated name/description with `[[keyword]]` markup), attaches the procedural icon (`skill.icon = icon.assetKey`), and shows the skill summary in the RESULT phase. On Continue, MapScene's `onComplete` pushes the skill onto **`runState.skills`** (full objects — woven skills exist in no catalog) and `createPlayerBattleState` appends them to the character's skills every subsequent battle. Redundant/incompatible picks are a **CHOICE-DRIVEN downside**: they deterministically contribute nothing and are surfaced via `synthesis.wastedReasons` (shown as "Wasted X — <reason>" on the result screen) so a weak weave reads as avoidable, not a dice roll. (The old "weave surges" injection is gone; `synthesis.injectedTags` is retained but empty.) All layout/visual tunables are named constants atop the scene; the skill_weave assets (incl. the 3 rarity option containers) are registered in [`main.js` ASSET_MAP](src/js/main.js:35) and the tag icon falls back to the gold-flame placeholder until per-tag art exists.

32. **Status effects (buffs/debuffs) are a general, data-driven system; their durations tick by TURN CYCLE.** The roster is the pure DATA catalog [`statusEffects.js`](src/js/data/statusEffects.js) (9 statuses: 6 debuffs, 3 buffs); ALL battle behavior lives in [`BattleController`](src/js/game/BattleController.js). The old one-off turn-scoped debuffs (`_silencedTurns`, `_attackOverride`) were **removed and unified** into this system — Silence is the `silenced` status and Exsanguinate's attack-pin is the `crippled` status (`attackValue`, default 1).
    - **State:** each combatant carries `statuses: []` (added in `_cloneState`, runtime-only). An entry is `{ id, kind, turns, _armed, sourceSide, attackValue?, savedAttack?, tickDamage? }`.
    - **Turn-cycle timing (the core rule):** a status lasts N cycles of the AFFECTED side (a cycle = that side holding control once). Ticked at the **START of the affected side's turn** in `_tickStatusesAtTurnStart` (called from `_completeTurnIntro`, NOT `_endTurn`). Each carries `_armed`, set at apply: SELF-applied (target IS the active side) → `_armed=true` (current turn is cycle 1, underway); OPPONENT-applied → `_armed=false` (cycle 1 begins at their next turn start). Per tick: `if (_armed) turns--; else _armed=true;` then remove when `turns<=0` (before any per-turn effect), else apply per-turn effects (Bleed). **"Active" for every game-logic check = the status is PRESENT in the list** (`_hasStatus`); durations only control persistence. Extra turns bypass `_completeTurnIntro`, so statuses do NOT re-tick mid extra-turn chain (correct — control was never lost). Bleed at turn start can be lethal, so `_completeTurnIntro` re-checks game over after the tick.
    - **API / apply:** `_applyStatus(targetState, id, { turns, attackValue }, applierSide)` (refresh keeps the longer duration + original saved data); `_hasStatus`/`_getStatus`/`_removeStatus`; `_canGainMana(side)` / `_canGainExtraTurn(side)`. Crippled snapshots `savedAttack` + pins attack (frozen against `_recomputeDynamicAttack`, re-pinned each frame by `_enforceStatusAttack`, restored on expiry). Bleed snapshots `tickDamage = ceil(applier.attack/2)` at apply.
    - **Per-status checkpoints:** Silence → `tryPlayerSkill` + `_doEnemyTurn` (skip skill casts, fall to `_doEnemySwap`); Cripple → attack pin (above); Enfeeble → `_canGainMana` gates the active-side mana credit in `_doRemove` + `_executeDestroyTiles`; Frozen → `_canGainExtraTurn` gates the extra-turn grants (`_enterShowMatch` 5+ match, the `extra_turn` skill effect, the passive `onExtraTurn` callback); Brittle/Intangible/Berserk → all in **`_applyDamage(target, amount, opts)`** (opts.attackerSide for Bleed). A Berserk attacker deals ×2 and ignores the target's defensive statuses; otherwise Brittle ×1.5 then Intangible clamps to 1 (wins); a Berserk target always takes ×2. **Berserk is a stub — no content applies it yet; its multipliers are tunable.** **(Barrier is no longer a status — it's a numeric shield pool absorbed in `MatchResolver.applyDamage` AFTER this mitigation, alongside armor; see decision #38.)**
    - **Skill application:** the `apply_status` effect type (`{ effectType:'apply_status', applyStatus:{ id, target:'self'\|'opponent', turns, attackValue? } }`) is the general way to apply any status from a skill (resolved in `_resolveEffect` → `_applyStatus`). The legacy `silence`/`set_attack` effect types still work as thin aliases.
    - **UI:** [`CharacterInfoPane`](src/js/ui/CharacterInfoPane.js) draws overlays over the portrait (`_renderStatusOverlays`, reading `state.statuses` via `updateFromState`). Display = "one big + count": the most-recent buff (tall crest) and most-recent debuff (wide crossed-blade X) render as large overlays at SEPARATELY tunable anchors (`STATUS_BUFF_*` / `STATUS_DEBUFF_*` — the two art shapes differ), plus a centered row of mini-badges for additional statuses and an optional remaining-turn count. Art from `ui_spritesheet_status_effects`. Buff/debuff hover-tooltips on the overlays are NOT wired yet (overlays are drawn manually, not registered UI elements).

The shared grammar trick: a "needs a color" mechanic consumes the woven element in the TARGET slot (via `takeColorType`, so it's not a dangling cost color) — except `consume`, which leaves its color dangling so it still pays the cost.
    - **`transmute`** (ACTION, mana economy) → `transmute_mana` effect (`{ transmuteMana:{ color, amount } }`, [`MatchResolver` SKILL_EFFECT_TYPES](src/js/game/MatchResolver.js); resolved in [`BattleController._resolveEffect`](src/js/game/BattleController.js)). Converts up to `amount` of the caster's OTHER mana into the woven destination color (most-abundant first, finite → no loop), Enfeeble-gated, fires `onGainMana`. A battery for next turn; fixes color screw / funds off-color woven spells. Added to `loopRiskColors` so the affinity fallback never charges in the transmuted color.
    - **`consume`** (ACTION, payoff) → `consume` effect (`{ consume:{ resource:'mana'|'armor'|'barrier', color?, divisor } }`). Deals `floor(poolSize / divisor)` damage — **1 damage per `divisor` units, capped at 1-per-2 (½ damage/mana)**, NO stat scaling (the payoff is hoarding a big pool; `divisor` rolls 2/3/4, `greater` sharpens it one step toward the 2 cap). Then SPENDS the pool. The woven `consume` tag emits `resource:'mana'` and binds to a woven color's LEFTOVER mana (the color stays dangling → still pays the cost, so you "over-buy then cash the rest"); no color → all leftover mana. The effect type ALSO supports `armor`/`barrier` so a future Warrior **Shield Bash** skill drops in — NOT added as a starting skill (characters keep exactly 2 skills). Damage routes through `_applyDamage`. (Not `<<n>>`-scalable.)
    - **`leech`** (MODIFIER, sustain) → not an effect type; a synthesizer post-pass attaches `damage.leech` (0..1 fraction) to every `damage` effect in the bag. [`BattleController._resolveEffect`](src/js/game/BattleController.js) DAMAGE case calls `_applyLeech(src, side, dealt, fraction)` → heals the caster for `floor(dealt × fraction)`. Wasted (downside reason) if the bag has no damage verb.
    - **`mark`** (ACTION, combo-setup) → `mark` effect (`{ mark:{ multiplier } }`) arms a one-time damage **MULTIPLIER** (×2, or ×3 with Greater) on `state.mark` (a numeric pool on the combatant, added in `_cloneState`, reset on transform; larger multiplier wins if re-applied). Consumed in the `_applyDamage` chokepoint on the attacker's NEXT damage instance (`dmg = round(dmg × mark)`, applied to raw damage before mitigation; skipped for reflected damage). Persists until consumed — NO timer, so it never depends on Extra Turn. Resolution order 88 (after this skill's own damage), so `mark + strike` in one weave banks for the NEXT hit, not a self-combo.
    - **`reflect`** (STATUS, self-buff) → the new **`reflecting`** buff in [`statusEffects.js`](src/js/data/statusEffects.js) (icon reuses the now-unused `buff_barrier` crest). While active, the owner **STILL takes the damage but ALSO deals the same amount back** to the attacker: in `_applyDamage`, a target with `reflecting` deals `result.actualDamage` (what just landed) back to the attacker (recursion-guarded by `this._reflecting`). No per-instance value — its only parameter is **duration** (the synthesizer's rolled value = turns, kept short since reflecting ALL damage is strong; priced via `POWER.reflectTurn`). **SFX:** when reflect fires it sets the one-shot `reflectTriggered` state flag → [`BattleScene`](src/js/ui/BattleScene.js) plays `sfx_generic_reflect_1` (a clip in the generic SFX sheet).
    - **`lock`** (ACTION, board control, **TARGETED**) → `lock_color` effect (`{ lockColor:{ color?, turns } }`). The player **clicks a tile** (the action claims the single targeting slot, `area:{radius:0}`); [`BattleController._executeLockColor`](src/js/game/BattleController.js) (dispatched from `tryTargetTile`) locks that tile's color (5 mana colors + skull) for **2–3 turns (2 minimum)**. Lock is **by COLOR** on [`BoardModel`](src/js/game/BoardModel.js) (`lockedColors` map + `lockColor`/`isColorLocked`/`tickLocks`, carried through `clone`), NOT per-cell — sidesteps gravity surgery. A locked color is **unmatchable** (skipped in `_scanLineRuns`) and **unmovable** (excluded from `getValidSwaps`; rejected by `tryPlayerSwap`), for BOTH sides — a denial tool. Ticks at each turn start (`board.tickLocks()` in `_completeTurnIntro`), but uses the status-style **`armed`** model: a lock applied mid-turn is ARMED (not decremented) at the very next turn start, so a 1-turn lock covers the OPPONENT's whole turn instead of expiring the instant the turn passes. A NON-targeted fallback path (`_resolveEffect` LOCK_COLOR, used by `random`-granted locks carrying a preset `color`, else `_mostAbundantBoardColor()`) also exists. Has the **`[[Lock]]`** keyword ([`keywordDefinitions.js`](src/js/data/keywordDefinitions.js)). Cast/resolve SFX uses the dedicated `sfx_generic_lock_1`/`_2` clips (`pickSkillSound` family `lock`, 2 versions). **`pickSkillSound` now picks the bag's most SALIENT action by `SOUND_PRIORITY`** (not pick-order), so a `lock + armor` spell plays the lock sound rather than gain-armor (lock outranks generic supports; damage outranks lock). Rendered by [`BoardPlaceholder._drawLockedTileOverlay`](src/js/ui/BoardPlaceholder.js) — the **`locked_tile`** sprite (in `ui_spritesheet_tiles`, name matches → no alias) drawn over any tile whose color is locked, plus a centered white turns-remaining number badge (`getLockTurns`). **Resolves at order 8 (BEFORE `shuffle` at 10)** so a woven `lock + shuffle` reads the clicked tile's color before the board scrambles (lock is by-color, so the right color stays locked through the shuffle). **Edge cases:** (a) a targeted skill that grants an extra turn WITHOUT a cascade (`lock + extra_turn`) now sets `state = PLAYER_TURN` in `tryTargetTile`'s extra-turn branch — previously it was left stuck in `TARGETING` (the "kept targeting / double-target" bug; cascade-entering targeted skills were unaffected since they route through `_finishResolving`). (b) [`BattleController._maybeAutoPassPlayer`](src/js/game/BattleController.js) auto-passes the player's turn when there is no movable tile (all-locked board → empty `getValidSwaps`) AND no castable skill, so a fully-locked board can't soft-lock — called at player turn start (`_completeTurnIntro`) and after a retained (extra) turn.

41. **Damage feedback is an accumulating per-side COUNTER (not per-hit text); mana matches fly whispy streams to the mana orbs.** Replaces the old per-instance floating "-x" damage text with two coordinated juice systems, both BattleScene-side (no battle-logic changes beyond augmenting `matchTextTriggers`):
    - **Damage counter** ([`DamageCounterEffect`](src/js/ui/DamageCounterEffect.js)). DAMAGE `floatingStatEvents` (kind `'damage'`, from the single `_applyDamage` chokepoint) route to [`BattleScene._addDamageToCounter(side, amount, maxHp)`](src/js/ui/BattleScene.js) instead of `_spawnStatTextEffect`. One stylized counter per side appears at BOARD CENTER (compact) and ACCUMULATES every hit in a sequence (3 → cascade +5 → shows 8), showing the running total + a CHAIN count (`34 DAMAGE` / `CHAIN x3`). It intensifies with RELATIVE damage (`total / (maxHp * INTENSITY_FULL_FRACTION)`): a gold→orange→red color ramp, larger font, stronger additive glow. Each hit replays a punchy tick — scale "punch" + rotational wobble (`PUNCH_*`), positional shake (`SHAKE_AMP`), glow flare (`FLARE_GLOW`), slash accents. **Finalize = end of the damage sequence:** the counter holds open while the board is resolving (BattleScene feeds `counter.resolving = (state RESOLVING/SWAPPING) && activeSide !== side` each frame, so a whole cascade stays ONE counter and finalizes promptly once it's the receiver's own turn); when no new damage arrives for `FINALIZE_IDLE_MS` while not resolving, it FINALIZES (number grows with a bounce, "DAMAGE"+chain fade out), then the bare number FLIES in an arc to the receiver's portrait (`setTarget`) shrinking, and IMPACTS with a flash + spark burst that fires `onImpact(intensity)` (BattleScene → screen shake). NOTE: actual HP/damage is applied earlier in battle logic (immediate) — the fly-to-portrait is purely ceremonial delivery, not a deferred damage application. BattleScene feeds the board-center-ish (`_getDamageCounterAnchor`, near the TOP of the grid — `DAMAGE_COUNTER_Y_FRAC`) via `setCenter` + the portrait (`setTarget`) anchors each frame. **Turn gating (two-phase TURN_INTRO):** so the damage fully delivers BEFORE the next turn is announced/acted, [`_endTurn`](src/js/game/BattleController.js) defers the turn announcement. TURN_INTRO now runs **Phase A** (silent hold — no "Player/Enemy Turn" popup — while a just-dealt damage counter flies to + impacts the target portrait) then **Phase B** ([`_beginTurnAnnouncement`](src/js/game/BattleController.js) raises `_turnAnnouncement` → the scene spawns the popup, then the normal `TURN_INTRO_DURATION` delay → `_completeTurnIntro` → the turn acts). The hold is driven by the scene-supplied gate [`BattleController.setTurnGate`](src/js/game/BattleController.js) → `BattleScene._hasPendingDamageDelivery()` (true while any counter is not `done` and not `delivered` — the counter's `delivered` getter flips true once impact fires); capped by `TURN_GATE_MAX_HOLD` (2000ms) so a stuck effect can't freeze the battle, and `_introAnnounced` starts true so the first turn (no damage pending) announces immediately. Extra turns bypass TURN_INTRO entirely, so they aren't gated (no turn passes). Managed per side in `BattleScene._damageCounters` (kept in `_floatingEffects`); a finalizing/done counter is replaced by a fresh one on the next hit. The other stat kinds (heal/armor/barrier/poison) still float as independent `FloatingTextEffect`s. All feel tunables are top-of-file consts in the effect; the number/label glyphs are authored sprites from `ui_spritesheet_combat_damage` (label `ui_animated_text_damage_chain_single_digit`/`_double_digit` chosen by chain digit count + `digit_0`…`digit_9`), fetched from the AssetManager (passed into the effect ctor).
    - **Mana streams** ([`ManaStreamEffect`](src/js/ui/ManaStreamEffect.js)). `matchTextTriggers` now carries every matched cell (`positions`, added in [`BattleController`](src/js/game/BattleController.js)). For each mana-color match (skull/inert excluded via `isMana`), [`BattleScene._spawnManaStream(trigger, activeSide)`](src/js/ui/BattleScene.js) flies a few thin glowing color-tinted wisps from the matched cells to the matching mana orb in the side that GAINED the mana (the active side; orb position via [`CharacterInfoPane.getManaOrbCenter(color)`](src/js/ui/CharacterInfoPane.js)). As the leading wisps land, the effect's `onArrive` callback pulses the orb ([`CharacterInfoPane.pulseManaOrb`](src/js/ui/CharacterInfoPane.js) → [`UIOrb.pulse()`](src/js/ui/UIOrb.js)): a slight, NON-intensifying scale bobble (`UIOrb.PULSE_*`, decayed in `update(dt)`, applied as a center-scale transform in `renderSelf`). The "+N" board match text is unchanged (still spawned alongside).

42. **Match-4+ resolves get an emphasis "freeze" beat + board-darken flourish.** When a 4+ match GRANTS AN EXTRA TURN, the board holds on the matched tiles for a brief configurable moment before cascades continue — not a full pause, just enough that the brain registers "something important happened".
    - **Controller** ([`BattleController`](src/js/game/BattleController.js)). In `_enterShowMatch`, when the extra-turn condition is met (`analysis.extraTurnTrigger && !_resumeTurnAfterResolve && _canGainExtraTurn` — the SAME gate that sets `_extraTurnEarned`, so turn-start setup cascades are excluded), it collects the positions of every `count >= 4` match into **`_match4Flourish`** `{ cells, color, side, durationMs }` and sets **`_match4FreezeMs`** to a per-side freeze. The SHOW_MATCH phase timer holds for `phaseMs + _match4FreezeMs` (the freeze is EXTRA hold on top of the normal ~400ms highlight), so `_doRemove` (and thus the cascade) waits out the beat. Freeze durations are the top-of-file **`MATCH4_FREEZE_MS`** (`{ player: 115, enemy: 75 }` ms — presentation timing, NOT speed-scaled; player's beat is longer). Both fields are cleared in `_doRemove`/`_beginResolving` and reset each `_enterShowMatch`; `_match4Flourish` is surfaced via `getState()`.
    - **Global hit-stop.** [`BattleController.isHitStopActive()`](src/js/game/BattleController.js) is true for the first `_match4FreezeMs` of the flourish's SHOW_MATCH. [`BattleScene.update`](src/js/ui/BattleScene.js) checks it right after `updateFromController()` and, while active, **freezes EVERYTHING** — it early-returns after updating ONLY `this._board` (so the flourish keeps playing), skipping `super.update` (panes/portraits/relic bars/attack animation), all `_floatingEffects` (damage counters, floating text, mana streams, turn-announcement images), `_particleEffects`, and `_screenShake`. The controller's phase timer still advances (it ran before the check), so the freeze self-terminates and the scene resumes from exactly where it held. (Live `<video>` portraits keep decoding — a ~120ms drift is negligible — everything update-driven stops.)
    - **Board render** ([`BoardPlaceholder._renderMatch4Flourish`](src/js/ui/BoardPlaceholder.js)). BattleScene passes `state.match4Flourish` to the board each frame. The board self-times off `_flourishTime` (advanced in `update`, reset when the flourish reference changes). During the beat it **darkens the whole board** (semi-transparent black), lays a soft warm **additive radial bloom** behind the matched tiles (overlapping per-cell radials + a hot white core merge into one continuous glow across the group), then **redraws the matched 4+ tiles ON TOP** with the tile ART additively brightened (sprite-over-sprite, so the glow follows the tile SHAPE, not a boxy square); wild frames follow. The tiles **POP by scaling the whole matched group about its shared centroid** (each tile grows AND shifts outward proportionally, riding an easeOutBack overshoot), so the cluster expands as one rigid unit and tiles NEVER overlap each other regardless of `growScale` — they only bulge over the surrounding darkened non-matched tiles. The darken/bloom/brighten/pop ride a fade-in → hold → fade-out **envelope entirely within the freeze window**, so it's a punch (not a lingering dim) and the normal highlighted board resumes for the rest of SHOW_MATCH. Applies to BOTH sides (enemy uses the shorter beat). Look tunables: **`MATCH4_FLOURISH`** (darken, bloom radius/alpha, core, tile brighten, optional `growScale`) + **`MATCH4_GLOW_COLORS`** (per-type glow color, as `"r,g,b"`).
