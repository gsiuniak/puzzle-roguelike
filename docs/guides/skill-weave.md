# Skill Weave

**Load this when:** touching the weave draft (the "Weave a Power" screen), the tag catalog, the synthesis rule engine, the weave RNG/balance tables, or the composited spell icons.

---

## Pipeline

```
roll weave shape (weaveConfig: rounds 2–4, tags-per-round 2–4)
  → draw tags per round (skillWeaveTags.drawTagsForRound — rarity-weighted, global pool)
  → player drafts one tag per round (SkillWeaveScene — commit on click, Back to undo)
  → synthesize the bag (skillSynthesizer.synthesize → a real castable skill:
       effects[], rolled magnitudes, continuous mana cost, name/description)
  → composite the icon (spellIcons.getSpellIcon → registered AssetManager canvas)
  → awarded: MapScene's onComplete deep-clones synthesis.skill onto runState.skills
       (createPlayerBattleState appends those to the catalog skills every battle)
```

## Tuning surfaces

| File | Exports | Content |
|------|---------|---------|
| [`src/js/data/weaveConfig.js`](../../src/js/data/weaveConfig.js) | `TAG_RARITY`, `RARITY_WEIGHTS`, `ROUNDS_PER_WEAVE_WEIGHTS`, `TAGS_PER_ROUND_WEIGHTS`, `TAG_VALUE_TABLES`, `pickWeightedKey`, `pickWeightedEntry`, `rollRoundsPerWeave`, `rollTagsPerRound`, `rollTagValue` | **All tunable RNG tables for Skill Weave synthesis** — the SINGLE place to retune the weave's randomness. Three layers: (1) **tag rarity** (`RARITY_WEIGHTS` common/uncommon/rare/legendary ≈ 60/25/10/5), (2) **weave shape** (`ROUNDS_PER_WEAVE_WEIGHTS` 2–4 ≈ 70/30/10, `TAGS_PER_ROUND_WEIGHTS` 2–4 ≈ 50/35/15), (3) **hidden per-tag value tables** (`TAG_VALUE_TABLES` keyed by tag id — action magnitudes like `create` 3..12 / `strike`+`blast` 4..12 (shared `DAMAGE_ROLL`) AND status durations, each with per-value weights — the "high-roll" layer), (3b) **woven damage scaling** (`DAMAGE_SCALING_WEIGHTS` + `rollDamageScalingPreset` — weighted draw of a `DAMAGE_SCALING_PRESETS` key; `DAMAGE_SCALING_POWER` folds the rolled multiplier into cost with a random luck discount) and the **`greater`** amplifier (`GREATER_CONFIG`: damage/create multipliers + surge chance), plus the **`DAMAGE_COLOR_SKEW`** strike/blast cost-color gradient (decision #35), (4) **choice-driven downsides (NO injection)** — the old `INJECTION_CONFIG` "weave surges" is GONE; redundant/incompatible picks now deterministically contribute nothing and are surfaced with a reason (see skillSynthesizer `wastedReasons`), (5) **cost color** (`COST_COLOR_WEIGHTS` — relative weights: firstElement/otherElement/actionAffinity stack onto an anyColor baseline; only the FALLBACK for a bag with no element tag, since a multi-element bag's cost colors are deterministic), (6) **mana cost** (`MANA_COST_CONFIG` + `computeManaCostTotal(power)`: CONTINUOUS — total ≈ clamp(round(power / `powerPerMana`) + jitter, `min`, `max`); `powerPerMana` (K≈1.7) is calibrated against the authored catalog so woven spells share its power-per-mana band; `max` is a high HARD ceiling so big spells hurt; the synthesizer SPLITS the total across the woven colors (`maxColors`) in pick order). Every table is a set of **relative weights** (NOT required to sum to 100 — normalized at pick time by `pickWeightedEntry`), so any single number can be tweaked in isolation. |

## Tag catalog

| File | Exports | Content |
|------|---------|---------|
| [`src/js/data/skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js) | `SKILL_WEAVE_TAGS`, `TAG_CATEGORY`, `DEFAULT_TAG_ICON`, `getTag`, `getTagLabel`, `getTagIcon`, `getTagRarity`, `drawTagsForRound` | **Tag catalog + rarity-weighted draw for the Skill Weave screen** ([`SkillWeaveScene`](../../src/js/scenes/SkillWeaveScene.js)). `SKILL_WEAVE_TAGS` is an id-keyed catalog (`{ id, label, category, rarity, icon }`): elements (red/blue/green/yellow/purple/skull), actions (**strike**/**blast** (the two damage TYPE tags — `strike` is a damaging spell that scales with Attack, `blast` scales with Magic; decision #35)/armor/create/destroy/convert/**change**/gain/heal/drain/**attack**/**magic** (the `attack`/`magic` tags permanently RAISE the caster's Attack/Magic stat — counterparts to each other, distinct from the strike/blast damage tags)/armor/**barrier** (a one-round MAGIC shield — like armor but scales with Magic ×2/3 and expires in a round; decision #38)/explode), shapes (row/column/area/tile/random), modifiers (extra_turn/wild/**all**/**greater** (magnitude amplifier + surge)), and status-effect tags (silence/cripple/enfeeble/brittle/intangible/berserk/bleed/frozen — synthesized into `apply_status` effects). **In synthesis `skull` and `wild` read as TILE TYPES** (create/convert/change targets), not dangling tags — `wild`'s floor is "create Wild tiles" so it never fizzles. **`all`** is a scope qualifier (`change`→mass convert, `destroy`+color→board-wide wipe, boosts `create`). **`change`** is the targeted single-tile recolor (à la the Mage's Arcane Inscription) — synthesized into a `convert_tile` effect whose destination color is influenced by a woven element (an `area` shape widens it to 3×3); reuses `convert`'s icon sprite. Each tag carries a `rarity` (`TAG_CATEGORY` classifies it for the draw + future synthesis). The **old positional `[action, element, shape]` grammar is REMOVED** — `drawTagsForRound({roundIndex, chosen, count, colorBias})` draws `count` distinct tags rarity-weighted from one global pool, excluding already-committed tags, with a soft guarantee that round 0 includes ≥1 ACTION tag. **`colorBias`** (element tag id → weight multiplier) slightly favors the player's affinity colors — their character's starting-skill colors (Warrior red/blue, Mage purple/yellow, Witch Doctor green/purple). MapScene computes them (`startingSkillColors`) and passes via `SkillWeaveScene.configure({affinityColors})`; the scene builds the bias using `weaveConfig.COLOR_AFFINITY_WEIGHT` (1.6). Hidden value rolls live in [`weaveConfig.js`](../../src/js/data/weaveConfig.js) `TAG_VALUE_TABLES`, not here. Icons fall back to `DEFAULT_TAG_ICON` (`skill_weave_tag_test`) until per-tag art exists. **To extend:** add a tag (id + label + category + rarity) — no scene changes needed. |

## Synthesis rules

| File | Exports | Content |
|------|---------|---------|
| [`src/js/data/skillSynthesizer.js`](../../src/js/data/skillSynthesizer.js) | `synthesize` | **Woven tag bag → REAL castable skill** (the rule engine). `synthesize(recipe)` returns `{ recipe, groups, rolledValues, usedTags, unusedTags, wastedReasons, injectedTags, power, skill, summary }` where `skill` is a full skillCatalog-shaped object (`{ id, name, descriptionLines (structured effect sentences, one per entry), description (the '\n'-joined form, with [[keyword]] markup), icon (filled by the scene), sound, cost, targeting?, area?, effects[] }`). **Reading grammar (the recipe reads as a sentence; structure is DETERMINISTIC, only magnitudes/cost are RNG; binding is ORDER-TOLERANT — `convert red yellow` ≡ `red convert yellow`, only conversion DIRECTION uses relative type order):** TILE TYPES = the 5 colors + `skull` + `wild`, consumed by tile-verbs (create/convert/change); a color used by no verb is "dangling" → it ONLY pays cost; `wild`/`skull` can't be cost so their FLOOR is "create" (never fizzle). `convert` (MASS by-type) / `change` (TARGETED single) read "… → destination" where the LAST woven type is the destination and the preceding one the source (rolled at synthesis if absent); `change + all` → mass convert; a `tile`/`area` shape on convert → targeted; `area` on change → 3×3 (so `change + wild` = change a tile INTO Wild). `destroy`/`explode` + shape → shaped targeted destruction (`+tile` = one tile for a cascade); `skull + destroy` (no shape) → destroy N Skulls (`destroy_tiles_by_type`); `destroy + all + color` → board-wide color wipe. `skull + strike/blast` → damage ALSO scales per Skull on the board (`damage.perSkull`). **Damage tags** (`strike` = Attack-scaling / `blast` = Magic-scaling) go through `emitDamage`: roll a scaling-multiplier preset → `damage.scaling { attack|magic: mult }`, description `Deal <<n>> [[phys]]/[[mag]]` (live value); cost rises with the multiplier (luck-discounted). **Heal** goes through `emitHeal` (scales off BOTH Attack and Magic at the fixed `_50` ×1/2-each preset, `Heal <<n>> HP`); **Armor** through `emitArmor` (scales with Attack at the fixed `_33` ×1/3 preset, `Gain <<n>> [[armor]]`); **Barrier** through `emitBarrier` (a one-round MAGIC shield — like armor but scales with Magic at the fixed `_66` ×2/3 preset, `Gain <<n>> [[barrier]]`; decision #38). **`greater`** multiplies ANY magnitude verb's output (create/damage/attack/magic/armor/barrier/heal/drain, ≥+1) OR widens an area destruction (3x3→5x5) + may surge a synergy effect (decision #35). `all` boosts `create`'s count; `create`+`wild` → WILD tiles, `create`+`skull` → Skulls; `drain` is color-agnostic (drains every color; any color is dangling→cost); `attack` → gain_attack, `magic` → gain_magic (permanent +Attack / +Magic for the battle); statuses → apply_status (buffs intangible/berserk → self, debuffs → opponent); `extra_turn` appends LAST (decision #4 ordering). **Canonical effect order:** effects are EMITTED in tag pick order, but just before assembly the `effects[]` array AND its paired `descriptionLines[]` are sorted IN LOCKSTEP into a fixed resolution order (`EFFECT_RESOLUTION_ORDER`: board-shaping shuffle→create→convert→destroy, then damage, then heal/armor/barrier, then stat/mana/status riders, `extra_turn` always last). The battle engine resolves a skill's effects top-to-bottom, so this makes what the player READS match the order things RESOLVE (effects[i] and lines[i] are pushed 1:1 per emit, so a stable index sort keeps them aligned; guarded on a length match). **CHOICE-DRIVEN downsides (NO injection)** — only genuine contradictions DETERMINISTICALLY contribute nothing (pure opportunity cost), reported in `wastedReasons` (tag id → reason, shown on the result screen as "Wasted X — <reason>"): an orphan shape (no verb used it), a 2nd targeted action (only one targeting slot), `all` with nothing to amplify, and a color no effect/cost could use. (`wild`/`skull` floor to create, so they never waste.) The old "weave surges" injection is gone (`injectedTags` retained but empty). **The `random` tag is the exception — a WILDCARD that ALWAYS pulls a bonus effect** (`emitRandomBonus`): it rolls one tag from the entire NON-color pool (`NON_COLOR_BONUS_TAGS` — actions/shapes/modifiers/statuses) and emits that tag's self-contained effect, rerolling only if the rolled tag needs the already-taken targeting slot. So `random` is never wasted. A verb-less bag falls back to a damage effect. **All magnitudes are hidden rolls** from `TAG_VALUE_TABLES`. **Mana cost is CONTINUOUS** — `computeManaCostTotal(power)` ≈ clamp(round(power / K≈1.7), 3, 15) (calibrated against catalog skills; `POWER` weights atop the file) — then `buildCost` SPLITS the total across the DANGLING colors (those not consumed by a tile-verb) in PICK ORDER (first pays the most, capped at `MANA_COST_CONFIG.maxColors`), so color order matters and a color does exactly one job (effect OR cost). A bag with no dangling color falls back to `buildAffinityCost` → the weighted `rollCostColor` (`COST_COLOR_WEIGHTS`), which leans toward the **character's affinity colors** (their starting-skill colors, passed as `synthesize(recipe, { affinityColors })` from the weave scene, weighted by `COST_COLOR_WEIGHTS.characterAffinity`); if the rolled color lands OFF-affinity, a **subsidy split** (`COST_AFFINITY_SUBSIDY`) moves a fraction of the cost into the character's primary color, yielding an easier-to-fund 2-color cost. (No `affinityColors` → neutral, old behavior.) **Names** come from a pattern×adjective×noun×suffix generator (`NAME_PATTERN_WEIGHTS`, large pools: `ELEMENT_ADJ` ~20/element, `ACTION_NOUNS` ~16-22/action, short "the"-free `TAG_SUFFIXES` per tag — now keyed by elements + actions too, so most bags earn a suffix — e.g. "Crimson Strike", "Lash of Winter") hard-capped at `NAME_MAX_LENGTH` (20 chars, the skill-button space budget; over-long candidates reroll, fallback = bare noun). **Resolve SFX** is chosen ONCE here by `pickSkillSound(actions, effects, costColor)`: it prefers the **generic SFX pool** (`sfx_audio_generic_sprite` — see SoundConfig) with a random version (`GENERIC_SOUND_BY_ACTION`), walking the bag's ACTIONS in pick order and voicing the FIRST that has a generic clip — so a multi-action spell whose PRIMARY action lacks a generic clip (e.g. `attack`) still draws from the generic pool via its other actions (damage/create/…) instead of an old `skill_*` sound. Color-aware families pick the relevant tile color (damage → cost color, create → created flavor incl. wild/skull); only when NO bag action maps to the pool (pure attack/heal/drain/shuffle) does it fall back to `ACTION_SOUND`. The chosen key is stored on `skill.sound` so the same clip plays for the rest of the run. Skill carries `woven: { recipe, rolledValues, power, injectedTags, scalingRolls }` provenance. Tests: `node sim/test-skill-synthesizer.mjs`. Called by `SkillWeaveScene._finishWeave`; awarded into `runState.skills` by MapScene's onComplete. |

| [`src/js/scenes/SkillWeaveScene.js`](../../src/js/scenes/SkillWeaveScene.js) | `SkillWeaveScene` | **"Weave a Power" skill reward screen** (full-canvas ritual, modeled on TitleScreen/GameOverScene). Replaces the "choose 1 of 3 finished skills" reward with a staged **tag draft**: the player builds a skill by picking one keyword tag per ROUND, filling a recipe whose length = the number of rounds. The **weave shape is rolled per entry** (`_rollWeavePlan` reading [`weaveConfig.js`](../../src/js/data/weaveConfig.js)): **2–4 rounds**, and each round offers **2–4 tag options** drawn **rarity-weighted** from one global pool (round 0 soft-guarantees an action tag). The old positional `[action, element, shape]` grammar is GONE — validity/meaning is resolved later at synthesis time. The background is **toggleable via the `USE_BACKGROUND_VIDEO` constant** (currently `false` → static `skill_weave_background` image). When `true` it plays a looping **video** (`video_skill_select_screen_bg.mp4` at `assets/audio/video/`, an off-DOM muted `<video>` drawn full-canvas each frame in `renderBackground` — same approach as BossIntroScene/VideoPortrait, NOT an AssetManager entry; `_createBackgroundVideo`/`_destroyBackgroundVideo` on enter/exit), with the static image as the until-decoded / autoplay-blocked fallback. Option plaque art is **rarity-suffixed** (`ui_skill_weave_option_container_<rarity>`; common uses the base) and the hover glow is rarity-tinted. ALL interactive UI (2–4 fanned/grid tag option plaques, the Recipe container + 2–4 slots that shrink to fit the rolled round count, and the Back/Confirm buttons — Back uses `ui_skill_weave_button`, Confirm uses the taller flaired `ui_skill_weave_button_confirm`, anchored by its body-center onto Back's center line so the labels align and the gem flair pokes up; label position/size are the `CONFIRM_BUTTON_*` consts) is drawn + hit-tested manually in design space via `_computeLayout()` (single source of truth shared by `render()` and input). **Interaction:** clicking a tag option **immediately commits** it into the next recipe slot and advances to the next step (hovering an option grows it slightly + adds a glow as the "this is what a click takes" cue); **Back** (disabled on step 0) removes the most recent tag and restores the previous step's exact options (kept on the `_steps` stack); **Confirm** is disabled until the recipe is full, then becomes "Weave Power" → `_finishWeave()` (it is ONLY the final resolve action, not a per-tag commit). Each round's options come from [`skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js) `drawTagsForRound({roundIndex, chosen, count})` (rarity-weighted, no repeats, soft action guarantee on round 0). **Crucible:** once the recipe is FULL but before "Weave Power" is pressed (`_complete && !_result`), a static crucible image (`ui_skill_weave_crucible`, from the `ui_spritesheet_skill_weave_elements` sheet — name matches directly, no alias) is drawn in the freed option band via `_renderCrucible` (centered, `CRUCIBLE_*` consts, soft fade-in keyed off `_crucibleTime`). **Orbs + beams:** one rarity orb per recipe tag (`ui_skill_weave_orb_<rarity>` from the same sheet) is positioned ringing the crucible (`_orbAnchors`/`_orbRects`, anchored by the orb's glowing-ball point `ORB_BALL_FRAC`, `ORB_*` consts), each continuously **beaming rarity-colored energy into the crucible center** (`ORB_BEAM_COLORS`: greyish-purple/green/purple/orange) via a sustained continuous-mode [`HarvestTendrilEffect`](../../src/js/ui/HarvestTendrilEffect.js) PER orb (`_crucibleBeams` is an ARRAY, built by `_ensureCrucibleBeams`: each beam = one orb ball center → crucible center, tinted by that tag's rarity). The beams + orbs render inside `_renderCrucible` (disc → orbs → additive beams ON TOP) and live only while complete-and-unconfirmed — `update` drops `_crucibleBeams` (ending the beams) the instant the state leaves complete (Back) or enters the result phase (Weave Power). A looping **`sfx_crucible`** SFX plays for the same window (`_startCrucibleSfx`/`_stopCrucibleSfx` via `AudioManager.playSfx({loop:true})` / `stopSfx`, `_crucibleSfxId`; also stopped in `onExit`). **`_finishWeave` calls [`skillSynthesizer.synthesize()`](../../src/js/data/skillSynthesizer.js)** (the REAL rule engine — emits a castable skill with effects, rolled magnitudes, randomized mana cost, generated name/description) AND generates the spell's procedural icon via [`getSpellIcon`](../../src/js/icons/spellIcons.js) (see "Spell icons" below), attaching it as `skill.icon`, then enters a **RESULT phase** (`_result` set): the woven icon reveals (grow+fade, `RESULT_*` consts) centered where the tag options used to fan out WITH the skill summary below it (`_renderResultSkillSummary` — name, cost line (MULTI-color aware; single color tinted by `MANA_TEXT_COLORS`, a split cost shown neutral), markup-stripped description lines, and a per-tag "Wasted X — <reason>" line for each unused tag from `synthesis.wastedReasons`; the recipe container is hidden in this phase since the summary supersedes it; layout = the `RESULT_*` consts), Back disables, and the confirm button relabels to **"Continue"** — a second confirm press (`_finishContinue`) fires the optional `_onComplete` callback (payload `{ recipe, synthesis, icon }`) and returns to `_returnScene`. **The award:** MapScene's `onComplete` deep-clones `synthesis.skill` onto `runState.skills`, and [`createPlayerBattleState`](../../src/js/data/playerStats.js) appends those to the character's catalog skills every battle — the woven spell is castable for the rest of the run. Configured via `configure({ onComplete, returnScene, runSeed })` (runSeed feeds icon generation); MapScene routes the `training` node here (see decision #31) and wires `onComplete` → `_handleBattleComplete` so the node completes on return. `onEnter` cross-fades music to `skill_weave_theme` (via `AudioManager.playMusic`); tag-pick plays `sfx_choose_tag`, Back plays `sfx_choose_tag_back`. Registered once in [`main.js`](../../src/js/main.js). |

## Spell icons

Runtime-assembled circular icons for synthesized (woven) spells — the icon is built by **layering authored spritesheet art with blend modes** (NOT procedural drawing). Layer stack: colored base mana-orb (bottom) → optional minor effect (MULTIPLY) → major effect (COLOR-DODGE) → `icon_border_2` cap (normal). The blend modes make the white effect sprites feel energized by the base color rather than pasted on. Two separable concerns + a cache layer:

| File | Exports | Responsibility |
|------|---------|----------------|
| [`src/js/icons/spellIconRecipe.js`](../../src/js/icons/spellIconRecipe.js) | `resolveIconPlan`, `hashString` | **Layer SELECTION (pure logic, no canvas).** `resolveIconPlan(tags, cost, spellId, assetManager?)` → `{ baseKey, minorKey, majorKey, borderKey, color, majorTag, minorTag, signature }`. **BASE** = the spell's dominant mana color from `cost` (highest-amount color; ties broken by the spell's first element tag; else neutral). **EFFECTS** = effect-bearing tags (actions/statuses/shapes/modifiers — elements only color the base) ranked by `EFFECT_TAG_PRIORITY`: top = MAJOR (the color-dodged subject), next distinct = MINOR (multiplied). A verb-less bag falls back to `DEFAULT_EFFECT_TAG` ('damage'). **BORDER** = `icon_border_2`. **Variants** (`<color>_base_<n>` / `foreground_<tag>_<n>`) are auto-discovered by probing the AssetManager (`isLoaded`), picked deterministically per spell; missing sprites degrade gracefully (skip / neutral / bare-prefix). `signature` = the resolved sprite keys (the cache key; two spells with identical layers share one icon). Unit tests: `node sim/test-spell-icon-recipe.mjs`. |
| [`src/js/icons/spellIconCompositor.js`](../../src/js/icons/spellIconCompositor.js) | `renderIcon`, `ICON_PIPELINE_VERSION`, `ICON_NATIVE_SIZE` | **Compositor (Canvas 2D).** `renderIcon(plan, assetManager, size=512)` → transparent S×S canvas, synchronous, fast (4 draws). Fetches each sliced sprite by key from the AssetManager and draws: (1) base full-size, source-over; (2) minor contained+centered (`MINOR_FIT`), `globalCompositeOperation='multiply'`; (3) major contained+centered (`MAJOR_FIT`), `'color-dodge'`; (4) border full-size, reset to `'source-over'` (never blended). No randomness — same plan → same pixels. Bump `ICON_PIPELINE_VERSION` (currently **3**) when the layer stack / blend order changes (it's in the cache key). |
| [`src/js/icons/spellIcons.js`](../../src/js/icons/spellIcons.js) | `getSpellIcon`, `clearSpellIconCache` | **Cache + integration.** `getSpellIcon({keywords, cost, spellId, assetManager?})` → `{ canvas, assetKey, plan }`; resolves the plan, renders once per `plan.signature + size + ICON_PIPELINE_VERSION`, and registers the canvas with the AssetManager under `spell_icon_<hash>` (via `AssetManager.registerCanvas`) so any UIImage/SkillButton can draw it through the normal asset-key path. `clearSpellIconCache()` is called from [`MapScene.resetForNewRun()`](../../src/js/scenes/MapScene.js). Wired in [`SkillWeaveScene._finishWeave`](../../src/js/scenes/SkillWeaveScene.js) (spellId `woven_<tags>`, `cost` from the synthesized skill) — the icon shows in the scene's RESULT phase, rides the `onComplete` payload, and is set as `skill.icon = icon.assetKey`. Dev validation grid: open `src/icon-debug.html` (renders N random tag combos through the real modules; click-to-inspect prints the plan). |

**The two source sheets** (`assets/sprites/skill_weave/`, registered in [`main.js` SPRITESHEET_MAP](../../src/js/main.js)): `ui_spritesheet_weave_base` (circular colored mana orbs, named `<color>_base_<n>`; `<color>` ∈ red/blue/green/yellow/purple/skull) and `ui_spritesheet_weave_generic` (white effect foreground sprites named `foreground_<tag>_<n>` using the weave tag ids, plus `icon_border_2`). **Sprite names must be semantic** (the AssetManager slices by sprite name) — a sheet packed with opaque `sprite_N` names won't resolve. To add a base color or effect: add the named sprite to the matching sheet — no code change (selection is name-driven). The old fully-procedural pipeline (FBM clouds / gradient-map LUT / `pngGlyphs.js` / `ui_spritesheet_weave_grayscale`) is **removed**.

| "Woven skill missing in battle / not awarded" | [`MapScene._transitionToSkillWeave`](../../src/js/scenes/MapScene.js) `onComplete` (pushes `synthesis.skill` → `runState.skills`) | [`createPlayerBattleState`](../../src/js/data/playerStats.js) appends `runState.skills` to the character's catalog skills each battle |

## Design decisions

| # | Decision | Why it matters here |
|---|----------|---------------------|
| [#31](../decisions/31-the-weave-a-power-skill-reward-is.md) | The "Weave a Power" skill reward is a layered-RNG tag draft + a synthesis step | The system's charter: all randomness/data lives OUTSIDE the scene (weaveConfig / skillWeaveTags / skillSynthesizer) |
| [#33](../decisions/33-spell-icons-for-woven-skills-are-composited.md) | Spell icons are COMPOSITED at runtime from authored spritesheet layers, deterministic per spell | The blend stack + name-driven sprite selection + `ICON_PIPELINE_VERSION` cache contract |
| [#34](../decisions/34-magic-stat-per-effect-damage-scaling-phys.md) | Magic stat + per-effect damage scaling + `[[phys]]`/`[[mag]]` keywords + `<<n>>` live-value markup | The scaling + live-description machinery every woven effect emits into |
| [#35](../decisions/35-woven-damage-scales-with-two-damage-type.md) | Woven damage scales, with two damage TYPE tags (`strike`/`blast`), a `greater` amplifier, live `<<n>>` descriptions | The damage-tag grammar, scaling-preset rolls, cost skew, and Greater/surge rules |
| [#38](../decisions/38-barrier-is-a-one-round-magic-shield.md) | Barrier is a one-round MAGIC shield (armor-like pool), NOT a status | Why `barrier` is an ACTION tag with an armor-like magnitude table and `emitBarrier` |
| [#39](../decisions/39-poison-is-a-numeric-stack-pool-not.md) | Poison is a numeric STACK pool, not a duration status | The `poison` weave tag (currently `disabled: true`) — its emit/pricing rules are intact but never drawn |
| [#40](../decisions/40-six-new-weave-mechanics-transmute-consume-leech.md) | Six weave mechanics — `transmute`, `consume`, `leech`, `mark`, `lock`, `reflect` | Their tag entries, magnitude rolls, `emit*` closures, and resolution-order slots |
