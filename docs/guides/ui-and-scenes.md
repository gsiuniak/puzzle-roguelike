## Engine services

Owned by SceneManager, created once in [`main.js`](../../src/js/main.js).

### CanvasApp — [`src/js/engine/CanvasApp.js`](../../src/js/engine/CanvasApp.js)

DPR-aware canvas, resize, clear, context access. **Per-scene wide viewport:** the design space is normally a fixed 1920×1080 contain-fit (pillar/letterbox bars), but `setSceneDesignWidth(w)` sets `designWidth` to a scene-requested FIXED width > 1920; the uniform contain-fit then does the rest — screens wider than `w:1080` absorb the extra width from the pillarbox bars at full size, narrower screens (e.g. exact 16:9) drop the scale so the full width still fits (the whole game renders slightly smaller, letterboxed/vertically centered). `designHeight` never changes. SceneManager applies it per scene from the scene's optional `preferredDesignWidth` field (null → classic fixed viewport). The viewport clip, input mapping (`cssToDesign`), and `onResize` all follow automatically. **Render DPR is capped** at `MAX_RENDER_DPR = 2` (main.js → `maxDpr` option; `?dprcap=N` URL override, `0` = uncapped) — never read raw `window.devicePixelRatio` in render code, use `app.dpr` or the live `ctx.getTransform()` (decision #51).

### GameLoop — [`src/js/engine/GameLoop.js`](../../src/js/engine/GameLoop.js)

requestAnimationFrame loop with delta time.

### InputManager — [`src/js/engine/InputManager.js`](../../src/js/engine/InputManager.js)

Mouse/touch/keyboard events, hit-testing, listener registry. **mousedown/mouseup fire only for the LEFT button (`e.button === 0`)** — right/middle clicks don't trigger game actions (right-click is handled via canvas `contextmenu`, e.g. targeting cancel). Touch is mirrored as mouse events (touchstart → mousemove+mousedown, …) and sets **`lastInputWasTouch`** (true on touch handlers, false on mouse) so scenes can branch touch vs desktop UX. Also fires `wheel` (x, y, deltaY in design space; preventDefault'd) — used by the battle Skills panel + loadout modal for internal list scrolling.

### AssetManager

AssetManager (spritesheets, aliases, runtime canvases) → see [assets-and-audio.md](./assets-and-audio.md).

## Scenes

### SceneManager — [`src/js/scenes/SceneManager.js`](../../src/js/scenes/SceneManager.js)

Scene registry, switchTo/fadeToScene, game loop tick, layout. On every scene swap (both `switchTo` and the mid-fade `_executeSceneSwitch`), `_applySceneViewport` feeds the scene's optional **`preferredDesignWidth`** field to `CanvasApp.setSceneDesignWidth` BEFORE `onEnter` — scenes without the field get the classic fixed 1920×1080 viewport; a scene with it (today only BattleScene) gets the wider fixed viewport. **Frame-time HUD:** with the `?perf` URL flag, main.js attaches a [`PerfHud`](../../src/js/engine/PerfHud.js) via `setPerfHud`; `_tick` then times its update/layout/render phases and the HUD draws fps / avg / p95 + phase breakdown top-left over every scene.

### LoadingScene — [`src/js/scenes/LoadingScene.js`](../../src/js/scenes/LoadingScene.js)

**Boot preload screen** (shown before TitleScreen). Minimal dark-fantasy look drawn entirely with canvas primitives (no asset dependency, so it appears on frame 1): full-canvas near-black base (`renderBackground`), radial vignette, centered "LOADING" text, and a thin **gold** glowing progress bar with end-cap flourishes. Polls `assetManager.progress` each frame (eased via `PROGRESS_LERP`) to fill the bar; falls back to a looping shimmer sweep if no progress is known. Fades to `TitleScreen` (`fadeToScene`, `FADE_DURATION`) once progress hits 1 AND `MIN_DISPLAY_MS` has elapsed (a small floor so it never just flashes — loading runs in parallel so this never delays loading). `setAssetManager(am)` is wired in [`main.js`](../../src/js/main.js). All visual/behavior tunables are named constants at the top of the file (`LOADING_TEXT_Y`, `BAR_Y`, `BAR_WIDTH`, `BAR_HEIGHT`, gold fill/glow colors, `FADE_DURATION`, `MIN_DISPLAY_MS`). Modeled on `TitleScreen`.

### TitleScreen — [`src/js/scenes/TitleScreen.js`](../../src/js/scenes/TitleScreen.js)

Cover-fit title image, fade-in, any-input → CharacterSelectScene.

### CharacterSelectScene — [`src/js/scenes/CharacterSelectScene.js`](../../src/js/scenes/CharacterSelectScene.js)

Character selection, splash cross-fade, info panel, aura effect, → MapScene. **Choose-hero intro video** (optional, per-def `splashVideo`): confirming a hero that has a `splashVideo` plays that hero's full-canvas video (off-DOM muted `<video>`, NOT an AssetManager entry — same cover-fit framing as its splash, drawn in `renderBackground` OVER the splash so there's no gap until the first frame decodes, an optional fade-in over the splash exists but is DISABLED (`CHOOSE_VIDEO_FADE_IN_MS` = 0 → instant swap + immediate play; set >0 to fade the video in from its first paintable frame, held PAUSED on frame 0 for the whole fade with `_startVideoPlayback()` firing once fully opaque, `CHOOSE_VIDEO_PLAY_FALLBACK_MS` safety if never paintable), quickly fades ALL the UI out (`_uiFadeAlpha` ramped over `UI_FADE_OUT_DURATION`, applied as an outer `globalAlpha` in `render()`; `_drawInfoPanelBackground` multiplies it in explicitly since it sets its own alpha), and DEFERS the `fadeToScene('MapScene')` until the video is within `CHOOSE_VIDEO_CROSSFADE_LEAD` of its end (or it ends/errors/`CHOOSE_VIDEO_MAX_DURATION` safety) so the scene cross-fades as the video finishes. Video is pre-buffered on enter + selection change (`_ensureVideoPreloaded`/`_buildVideo`) and torn down in `onExit` (`_destroyVideo`); input is locked while the intro plays. Heroes WITHOUT a `splashVideo` confirm instantly (old behavior). Flow split: `_chooseHero` → `_beginChooseIntro` (video) or `_performSceneTransition` (immediate). All three heroes have videos today. **Growth panel** (`_buildGrowthSection` → `this._growthPanel`, a FREE-FLOATING scene-root container anchored near the bottom-right of the screen in `layoutChildren` — NOT part of the info panel; rebuilt per selection change): shows the character's per-victory `growthPlan` as HP/Atk/Mag rows of 5 diamond blips (filled `character_select_growth_fill` vs empty `_growth_outline`), titled "Growth" with the `_growth_flair_left`/`_right` flourishes + `_growth_flair_bottom` underneath. Blip scaling = module-level `growthBlips()`: maxHp → `round(growth) − 1` blips; attack/magic → `floor(growth × 5)` capped at 5 (1/level = 5 blips, ≈0.334/level = 1). Tunables in `UI.growth`.

### GameOverScene — [`src/js/scenes/GameOverScene.js`](../../src/js/scenes/GameOverScene.js)

**Player-defeat scene.** Full-canvas `battle_background_game_over` (cover-fit, drawn in `renderBackground` so it covers the bars), short fade-in. `onEnter` cross-fades music to `game_over_theme` (via `AudioManager.playMusic`, which fades the outgoing battle track out as this fades in). ### BossIntroScene — [`src/js/scenes/BossIntroScene.js`](../../src/js/scenes/BossIntroScene.js)

**Pre-boss video cutscene** (full-canvas, no audio). Plays an off-DOM muted `<video>` whose frames are drawn to the canvas each frame in `renderBackground` via `CanvasApp.drawFullCanvasImage` (on `loadedmetadata` it copies `videoWidth/Height` → `video.width/height` so the cover-fit math works; black shows until `readyState >= 2`). Configured per use via `configure({ videoSrc, musicKey, isSpecialTrack, nextScene })`. **Music is deferred to the first paintable frame, NOT started on entry:** `update()` calls `_startMusic()` (→ `AudioManager.startBattleMusic(musicKey, isSpecialTrack)`) the instant `video.readyState >= 2` (the same gate `renderBackground` uses), so a slow-buffering video can't play music over a black screen — picture + music begin together. `_requestFinish` also calls `_startMusic()` as a fallback so the non-rendering end paths (autoplay-block/error/skip/timeout) still hand a playing track to the battle. Either way the track routes through `startBattleMusic`, so the **following BattleScene treats it as already-playing and does NOT restart it** (music plays continuously through the cross-fade). **Preloading:** `preloadVideo(videoSrc)` builds + `.load()`s the off-DOM `<video>` ahead of time (without playing it) so its first frame is decoded before the cutscene starts; `MapScene._maybePreloadBossIntro()` calls it on every map entry (idempotent per src). `onEnter`→`_startPlayback()` reuses the preloaded element when its src matches (`_preloadedSrc`), else builds fresh; `_destroyVideo` removes all retained listeners and clears `_preloadedSrc`. Ends on the video's `ended` event (~15s), or on `error` / autoplay-block (`play().catch`) / `_maxDuration` safety timeout / any-input skip (after `_skipGrace`). All end paths set `_pendingFinish`; the actual `fadeToScene(nextScene)` is deferred to `update()` until no SceneManager transition is in flight (fadeToScene is a no-op mid-transition). `onExit` tears down the video but NEVER touches the music. Registered once in [`main.js`](../../src/js/main.js); MapScene routes here when an enemy def has `introVideo` (see decision #28). Modeled on `TitleScreen`/`GameOverScene`.

### SkillWeaveScene — [`src/js/scenes/SkillWeaveScene.js`](../../src/js/scenes/SkillWeaveScene.js)

> The synthesis rules (tags, RNG tables, `synthesize()`, spell icons) live in [skill-weave.md](./skill-weave.md). This section is the SCENE.

**"Weave a Power" skill reward screen** (full-canvas ritual, modeled on TitleScreen/GameOverScene). Replaces the "choose 1 of 3 finished skills" reward with a staged **tag draft**: the player builds a skill by picking one keyword tag per ROUND, filling a recipe whose length = the number of rounds. The **weave shape is rolled per entry** (`_rollWeavePlan` reading [`weaveConfig.js`](../../src/js/data/weaveConfig.js)): **2–4 rounds**, and each round offers **2–4 tag options** drawn **rarity-weighted** from one global pool (round 0 soft-guarantees an action tag). The old positional `[action, element, shape]` grammar is GONE — validity/meaning is resolved later at synthesis time. The background is **toggleable via the `USE_BACKGROUND_VIDEO` constant** (currently `false` → static `skill_weave_background` image). When `true` it plays a looping **video** (`video_skill_select_screen_bg.mp4` at `assets/audio/video/`, an off-DOM muted `<video>` drawn full-canvas each frame in `renderBackground` — same approach as BossIntroScene/VideoPortrait, NOT an AssetManager entry; `_createBackgroundVideo`/`_destroyBackgroundVideo` on enter/exit), with the static image as the until-decoded / autoplay-blocked fallback. Option plaque art is **rarity-suffixed** (`ui_skill_weave_option_container_<rarity>`; common uses the base) and the hover glow is rarity-tinted. ALL interactive UI (2–4 fanned/grid tag option plaques, the Recipe container + 2–4 slots that shrink to fit the rolled round count, and the Back/Confirm buttons — Back uses `ui_skill_weave_button`, Confirm uses the taller flaired `ui_skill_weave_button_confirm`, anchored by its body-center onto Back's center line so the labels align and the gem flair pokes up; label position/size are the `CONFIRM_BUTTON_*` consts) is drawn + hit-tested manually in design space via `_computeLayout()` (single source of truth shared by `render()` and input). **Interaction:** clicking a tag option **immediately commits** it into the next recipe slot and advances to the next step (hovering an option grows it slightly + adds a glow as the "this is what a click takes" cue); **Back** (disabled on step 0) removes the most recent tag and restores the previous step's exact options (kept on the `_steps` stack); **Confirm** is disabled until the recipe is full, then becomes "Weave Power" → `_finishWeave()` (it is ONLY the final resolve action, not a per-tag commit). Each round's options come from [`skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js) `drawTagsForRound({roundIndex, chosen, count})` (rarity-weighted, no repeats, soft action guarantee on round 0). **Crucible:** once the recipe is FULL but before "Weave Power" is pressed (`_complete && !_result`), a static crucible image (`ui_skill_weave_crucible`, from the `ui_spritesheet_skill_weave_elements` sheet — name matches directly, no alias) is drawn in the freed option band via `_renderCrucible` (centered, `CRUCIBLE_*` consts, soft fade-in keyed off `_crucibleTime`). **Orbs + beams:** one rarity orb per recipe tag (`ui_skill_weave_orb_<rarity>` from the same sheet) is positioned ringing the crucible (`_orbAnchors`/`_orbRects`, anchored by the orb's glowing-ball point `ORB_BALL_FRAC`, `ORB_*` consts), each continuously **beaming rarity-colored energy into the crucible center** (`ORB_BEAM_COLORS`: greyish-purple/green/purple/orange) via a sustained continuous-mode [`HarvestTendrilEffect`](../../src/js/ui/HarvestTendrilEffect.js) PER orb (`_crucibleBeams` is an ARRAY, built by `_ensureCrucibleBeams`: each beam = one orb ball center → crucible center, tinted by that tag's rarity). The beams + orbs render inside `_renderCrucible` (disc → orbs → additive beams ON TOP) and live only while complete-and-unconfirmed — `update` drops `_crucibleBeams` (ending the beams) the instant the state leaves complete (Back) or enters the result phase (Weave Power). A looping **`sfx_crucible`** SFX plays for the same window (`_startCrucibleSfx`/`_stopCrucibleSfx` via `AudioManager.playSfx({loop:true})` / `stopSfx`, `_crucibleSfxId`; also stopped in `onExit`). **`_finishWeave` calls [`skillSynthesizer.synthesize()`](../../src/js/data/skillSynthesizer.js)** (the REAL rule engine — emits a castable skill with effects, rolled magnitudes, randomized mana cost, generated name/description) AND generates the spell's procedural icon via [`getSpellIcon`](../../src/js/icons/spellIcons.js), attaching it as `skill.icon`, then enters a **RESULT phase** (`_result` set): the woven icon reveals (grow+fade, `RESULT_*` consts) centered where the tag options used to fan out WITH the skill summary below it (`_renderResultSkillSummary` — name, cost line (MULTI-color aware; single color tinted by `MANA_TEXT_COLORS`, a split cost shown neutral), markup-stripped description lines, and a per-tag "Wasted X — <reason>" line for each unused tag from `synthesis.wastedReasons`; the recipe container is hidden in this phase since the summary supersedes it; layout = the `RESULT_*` consts), Back disables, and the confirm button relabels to **"Continue"** — a second confirm press (`_finishContinue`) fires the optional `_onComplete` callback (payload `{ recipe, synthesis, icon }`) and returns to `_returnScene`. **The award:** MapScene's `onComplete` deep-clones `synthesis.skill` onto `runState.skills`, and [`createPlayerBattleState`](../../src/js/data/playerStats.js) appends those to the character's catalog skills every battle — the woven spell is castable for the rest of the run. Configured via `configure({ onComplete, returnScene, runSeed })` (runSeed feeds icon generation); MapScene routes the `training` node here (see decision #31) and wires `onComplete` → `_handleBattleComplete` so the node completes on return. `onEnter` cross-fades music to `skill_weave_theme` (via `AudioManager.playMusic`); tag-pick plays `sfx_choose_tag`, Back plays `sfx_choose_tag_back`. Registered once in [`main.js`](../../src/js/main.js).

### BattleScene — [`src/js/ui/BattleScene.js`](../../src/js/ui/BattleScene.js)

**Layout.** MainRow = player `RelicBar` | 3 character columns (player | board+combat-log center | enemy) | enemy `RelicBar`, centered with a negative gap (`MAIN_ROW_GAP` -32 — the board art's visible rails sit ~38px inside its square (transparent crest headroom), so the panels overlap the board RECT by 32px while leaving ~6px of visible daylight to the rails; the character panel art is tightly cropped, so don't exceed the board margin). Row budget at 2080: 2×90 relic + 2×440 side + 1080 center (`CENTER_COL_WIDTH` = the full-height 1080 board square; `MAIN_ROW_PADDING` is zero) − 128 = 2012, centered.

**Wide battle viewport:** the scene sets `preferredDesignWidth = BATTLE_DESIGN_WIDTH` (2080 — THE panel-width knob), a FIXED design width (see CanvasApp `setSceneDesignWidth`): wide screens absorb the extra 160px from the pillarbox bars at full size, narrower screens (16:9) scale the whole game down ~8% (letterboxed) so the width still fits. The scene's `layoutChildren()` override hands the extra width to the two side character columns (`SIDE_COL_WIDTH` 360 `+ extra/2` = 440 each) + widens `mainRow.maxWidth` by `extra` — the fixed-width center (board) column is untouched. `SIDE_COL_TOP_MARGIN` is THE knob for the side panels' vertical start. The two relic bars mirror each other: the player bar (`RELIC_COL_WIDTH`) floats left of the player panel; the enemy bar (`ENEMY_RELIC_COL_WIDTH` / `ENEMY_RELIC_BAR_PADDING`) floats right of the enemy panel and is fed from `enemyState.relics`.

Input handling, visual effects, game-over routing (**victory** → RewardOverlay → MapScene; **defeat** → `fadeToScene('GameOverScene')`, no overlay/return-to-map). Hidden turn label retained for backwards-compat (state/data binding only — visual display disabled).

**Corner action buttons:** two 60×60 icons (`battle_button_skip` / `battle_button_map`) stacked in the FAR physical top-right corner — drawn in `renderForeground` via `_renderCornerButtons` (anchored past the design viewport using `app.cssToDesign(cssWidth, 0)`, hit-tested in design space by `_handleCornerButtonClick`/`_getCornerButtonRects`). Skip → `_debugWinBattle()` (same as the 'K' key, force-wins). Map → opens the MapView overlay; while the overlay is open, clicking anywhere closes it (handled at the top of `_handleMouseDown`).

**Below them sits a smaller "?" HINT button** (canvas-primitive disc + gold "?" — no asset; `HINT_BUTTON_SIZE`, dimmed outside PLAYER_TURN) — **UPGRADED 2026-07-08 to full-ACTION hints from the champion formula policy (decision #45)**: click (or the **'h' key** — same path, no-op under modal overlays/map overlay) → `_requestHint()` → `_getSuggestedActionCached()` (the [`BattleController.getSuggestedAction()`](../../src/js/game/BattleController.js) champion-policy result, computed AT MOST once per player turn; the idle hint GLINT keeps its OWN simple-MoveAdvisor cache `_getSuggestedMoveCached` — both invalidated when state leaves PLAYER_TURN + on skill casts/loadout changes via `_invalidateSuggestedMove`; weights fetched async in onEnter via [`ai/hintWeights.js`](../../src/js/game/ai/hintWeights.js) `loadHintWeights`). Presentation by action type — **SWAP**: the two cells get the pulsing gold outline + double-headed arrow (`_renderHintHighlight`, inside the shake transform) and the gauntlet cursor "drags" cell A→B; **CAST**: the suggested card is auto-scrolled into view (`SkillsPane.scrollToSkill`) and the cursor taps it, then (targeted casts) glides to the target and the hit cells get a translucent gold ghost (`_hintTargetCells` pass in `_renderHintHighlight`, `HINT_TARGET_FILL_ALPHA`). The cursor is a [`HintCursorEffect`](../../src/js/ui/HintCursorEffect.js) (the `ui_hint_cursor` gauntlet art) whose waypoints are recomputed EVERY FRAME from live layout (`_computeHintWaypoints` — board cell centers + `SkillsPane.getCardRect`, clamped into the list's visible band); a nameplate BANNER (`_renderHintBanner`, same `ui_skill_nameplate` idiom as the targeting prompt — the two states are mutually exclusive) shows the action's `description` ("Cast Fracture on the marked row to deal 6 damage and earn an extra turn"). Cursor+banner render via `_renderHintOverlay` (design space, outside the shake transform, hidden under modal overlays). Self-times out after `HINT_DURATION_MS` (swap) / `HINT_CAST_DURATION_MS` (cast; fade tail `HINT_FADE_MS`) and clears EARLY the moment the player acts (state leaves PLAYER_TURN — lifecycle in `update()`, which also drives the cursor). Tunables: `CORNER_BUTTON_SIZE` / `CORNER_BUTTON_GAP` / `CORNER_BUTTON_MARGIN` / `HINT_*`.

**Targeting controls (device-branched, via `_isTouchInput()` → `InputManager.lastInputWasTouch`):** while in TARGETING a button row is drawn below the board (design space, `_renderTargetingControls`). **Desktop (mouse):** a board click casts instantly (`tryTargetTile`); only a single centered **Cancel** button shows. **Touch:** a tap/drag only POSITIONS the preview (`setTargetHover`) and a **Cancel | Cast** pair shows — **Cast** (`confirmTarget` → `tryTargetTile` at the preview cell) commits. Both modes: Cancel button / ESC / right-click abort; Enter confirms. Targeting seeds a default center target (`BattleController._setDefaultTarget`) so the area overlay (and touch Cast) work immediately. **The mousemove targeting reposition is gated by `_pointOverTargetingButton(x,y)`** — the buttons can overlap the board's lower rows, and on touch a tap fires mousemove BEFORE mousedown, so without the guard tapping Cast would re-target the cell under the button and cast there (the "casts in a different area" bug). Buttons are the authored `ui_skill_confirm` / `ui_skill_cancel` sprites (from `ui_spritesheet_character_pane`), drawn by `_drawTargetButton` with width derived from the art aspect (`_targetBtnAspect`) and a centered "Confirm"/"Cancel" label over the art (`TARGET_BTN_LABEL_*`); a "Casting &lt;skill&gt;" prompt is rendered on the `ui_skill_nameplate` banner centered at the top of the screen (`TARGET_NAMEPLATE_*` / `TARGET_PROMPT_*`; text auto-shrinks to fit the plate). **Right-click cancel works because [`InputManager`](../../src/js/engine/InputManager.js) only fires mousedown/mouseup for the LEFT button (`e.button === 0`)** — otherwise a right-click's mousedown would instant-cast (desktop) before the `contextmenu` handler could cancel. The buttons are semi-transparent (`TARGET_BTN_ALPHA`), popping to `TARGET_BTN_HOVER_ALPHA` on hover. Tunables: `TARGET_BTN_H/GAP`, `TARGET_BTN_CENTER_Y`, `TARGET_BTN_HOVER_SCALE`, `TARGET_BTN_ALPHA`/`TARGET_BTN_HOVER_ALPHA`, `TARGET_BTN_LABEL_*`.

### Scene lifecycle

Each scene must implement `onEnter()` and `onExit()`. Scenes receive `_sceneManager` back-reference from SceneManager.

### Scene render pipeline (per frame)

```
CanvasApp.clear()              — fills entire physical canvas with one color (or barFillImage)
scene.renderBackground(ctx)?   — OPTIONAL hook. Paints full-canvas backgrounds covering letterbox/pillarbox bars (use CanvasApp.drawFullCanvasImage / fillFullCanvas)
CanvasApp.beginViewportClip()  — clips to 1920×1080 design space
scene.render(ctx)              — normal UI rendering (clipped to design space)
CanvasApp.endViewportClip()
scene.renderForeground(ctx)?   — OPTIONAL hook. Full-canvas overlays on top of UI (e.g. reward splash, map overlay backdrop)
SceneManager transition fade   — full-canvas black overlay (via CanvasApp.fillFullCanvas)
```

Use `renderBackground` for splashes that sit BEHIND the scene's UI but must cover the bars. Use `renderForeground` for splashes/backdrops that sit ON TOP of the scene's UI but must cover the bars. UI inside the design viewport is drawn from `render()` as usual.

#### VideoPortrait — [`src/js/ui/VideoPortrait.js`](../../src/js/ui/VideoPortrait.js)

**Live chroma-keyed video portrait.** Subclass of `UIImage` whose "image" is the current frame of a muted, looping, off-DOM `<video>` with the chroma key color keyed to transparent. Each render it draws the frame into an offscreen canvas (capped to `PROCESS_MAX_DIM`, `willReadFrequently`), zeroes the alpha of every pixel whose squared RGB distance to `keyColor` (default `KEY_COLOR` = the green `#a4f885` backdrop) is within `keyToleranceSq` (default `KEY_TOLERANCE` 80 — tolerant of mp4 compression spreading the flat fill), and returns that canvas from `getImage()` so `UIImage.renderSelf` cover-fits it like a normal sprite (keyed backdrop → panel shows through). **The keying pass only runs when the video has a NEW decoded frame** — gated by `requestVideoFrameCallback` where supported (fallback: a ~30fps time throttle), so the getImageData/pixel-loop/putImageData cost tracks the video's ~24-30fps, not the 60fps render rate (the old `currentTime` equality check never held, so it keyed every render frame — a constant mobile drain in Malakor fights). Falls back to the static portrait sprite (ctor `fallbackAssetKey`) until the first frame decodes. Constructed by `CharacterInfoPane` when its data carries `portraitVideo`; `destroy()` releases the `<video>` (called on pane rebuild and `BattleScene.onExit`). Not an AssetManager entry — owns its own `<video>` (like `BossIntroScene`).

#### UIProgressBar — [`src/js/ui/UIProgressBar.js`](../../src/js/ui/UIProgressBar.js)

Health bar with fill, border, color interpolation. **Damage/heal change animations** (both cosmetic, self-driven by `update(dt)` — no caller wiring): on a drop the fill chunks down instantly and the just-lost slice lingers as a white **ghost bar** (holds `GHOST_HOLD_MS` so combo hits pool, then drains at a bar-relative rate; `ghostColor`/`ghostAlpha`); on a rise the fill HOLDS at the pre-heal value while a light-green **heal bar** FILLS UP from there to the new HP (`HEAL_GROW_MS`, bar-relative), holds (`HEAL_HOLD_MS`), then fades out (`HEAL_FADE_MS`) revealing the normal fill beneath — the mirrored opposite of the ghost (`healColor`/`healAlpha`). Damage cancels an in-flight heal fill; a heal snaps the ghost away. Optional **`armorValue`** draws a semi-transparent blue ARMOR overlay (`armorColor`/`armorFillAlpha`/`armorOverlayAlpha`) over the fill, hugging the right edge of current health: it fills the empty-health region first (forward), then extends BACKWARD over the red fill as a translucent overlay when armor exceeds the missing health — a fixed-width "padded effective HP" read. Visible width is naturally capped at the full bar; drawn between fill and border so the label stays on top. #### SpriteSheetAnimation — [`src/js/ui/SpriteSheetAnimation.js`](../../src/js/ui/SpriteSheetAnimation.js)

**PROOF OF CONCEPT (may be removed).** Plays a packed, alpha-TRIMMED spritesheet animation ONCE over a target rect, honoring each frame's `trim_x/trim_y/source_w/source_h` so a trimmed sequence doesn't jitter. Plays in **frame-NAME order** (numeric suffix of the sprite name, e.g. `frame_00001_`…); the JSON `index` field is IGNORED for ordering (some packers set it to bin-packing order, which scrambles playback). Draws each frame's source rect directly from the FULL sheet image (`am.get(sheetKey)`) — NOT the AssetManager-sliced sprites, which drop the trim offsets — mapping the virtual source frame onto an aspect-correct box centered on the anchor. Reads the JSON sidecar itself (module-cached fetch). **First-play stutter fix:** the static `SpriteSheetAnimation.preload(sheetKey, jsonPath, am)` prefetches the JSON AND **PINS a decoded `ImageBitmap` of the sheet** (module cache, once per sheet) — unlike an HTMLImageElement's decoded pixels (browser image cache, evictable under memory pressure → a synchronous multi-MB re-decode hitch on the next draw), a pinned bitmap stays decoded for its lifetime, so battle-time draws can never re-decode; `render()` prefers the pinned bitmap over `am.get(sheetKey)`, and the ctor re-attempts the pin as a safety net. ### Visual effects

All of these follow the externally-managed effect contract (`update(dt)` / `render(ctx)` / `done`) and live in BattleScene's `_floatingEffects` (unless noted).

#### FloatingImageEffect — [`src/js/ui/FloatingImageEffect.js`](../../src/js/ui/FloatingImageEffect.js)

Animated floating image (turn announcement, extra turn) with grow/settle/hold/fade phases. Renders with `imageSmoothingEnabled = true` (high quality) — the art is detailed/glow-heavy and is scaled to a fractional, animating size, so nearest-neighbour would alias the edges (this matters more now the art is sliced from `ui_spritesheet_animated_text` at full res and resampled to the board-relative target size).

#### FloatingTextEffect — [`src/js/ui/FloatingTextEffect.js`](../../src/js/ui/FloatingTextEffect.js)

Floating text (grow/settle/hold/fade, optional upward drift via `config.riseDistance`) at a screen coord. Used for static "+N" match-count text (riseDistance 0) AND floating-combat-text over portraits for the NON-damage stat events: green "+x" heal / blue "+x" armor / purple "+x" barrier / green "-x" poison (spawned by `BattleScene._spawnStatTextEffect` from `getState().floatingStatEvents`; each instance is independent). **Damage no longer uses this** — it accumulates into [`DamageCounterEffect`](../../src/js/ui/DamageCounterEffect.js) instead (decision #41).

#### DamageCounterEffect — [`src/js/ui/DamageCounterEffect.js`](../../src/js/ui/DamageCounterEffect.js)

**Accumulating combat-damage counter centered in the receiver's info column** (replaces per-hit floating "-x" damage text). A single stylized counter appears centered in the RECEIVING side's info column (the name/class/stats column beside the portrait, via [`CharacterInfoPane.getInfoColumnRect()`](../../src/js/ui/CharacterInfoPane.js); fallback = `DAMAGE_COUNTER_BAR_LIFT` px above the HP bar until laid out) and ACCUMULATES every hit of a damage sequence, showing the running total + a chain count (`34 DAMAGE` / `CHAIN x3`). Four-phase timeline: **ACCUMULATE** (compact over the bar; each hit bumps total + `chain` and replays a punchy tick — scale pop `PUNCH_*`, positional `SHAKE_AMP` shake, and `_drawSlashes` slash accents), **FINALIZE** (no new damage for `FINALIZE_IDLE_MS` while the board has settled → the WHOLE block pops to `FINAL_SCALE` via `easeOutBack`/`FINAL_BACK` over `FINAL_GROW_MS` and holds `FINAL_HOLD_MS`; words do NOT fade), **FLY** (the ENTIRE composed block — number + DAMAGE + CHAIN — arcs to the receiver portrait as ONE unit over `FLY_MS` with `FLY_ARC_LIFT` bow + ease-in, shrinking to `FLY_END_SCALE`), **IMPACT** (radial flash + spark fan `_drawImpactBurst`, fires `onImpact(intensity)`, whole block fades over `IMPACT_MS`). The big number's SIZE ramps with damage RELATIVE to receiver max HP (`INTENSITY_FULL_FRACTION`; `NUMBER_MIN_H`→`NUMBER_MAX_H`); the intensity ramp also tints the impact burst + slash accents. **Text rendering is SPRITE-BASED** (the old EmberForge forged-text engine was removed): all glyphs are authored sprites sliced from **`ui_spritesheet_combat_damage`** (registered in [`main.js` SPRITESHEET_MAP](../../src/js/main.js)) — a **"DAMAGE / CHAIN X" label image** ("DAMAGE" big over "CHAIN X" smaller, on its plaque) in two plaque-width variants — **`ui_animated_text_damage_chain_single_digit`** (1-digit chain) / **`ui_animated_text_damage_chain_double_digit`** (10+, wider plaque), picked by `_labelSprite()` on the chain count's digit count — plus per-digit glyphs **`digit_0`…`digit_9`** reused for BOTH the big damage total and the chain count. `_drawBlock` (shared by the centered + flying renders) composes them: the big number (digit sprites, `_drawDigits` centered) on top, the label sprite below, and the chain-count digits drawn ON TOP of the label's baked "CHAIN X" line (placed by the `CHAIN_DIGIT_*` fractions of the displayed label rect). Digits are laid out top-aligned and scaled by `glyphH / DIGIT_NATIVE_H` (a uniform factor; frames share a top origin — `trim_y=0`) so a run stays on a consistent baseline; widths come from each sliced sprite's own `.width`. The effect takes the **AssetManager** in its ctor (`new DamageCounterEffect(x, y, assetManager)`) and fetches sprites via `assetManager.get('digit_N')` / `get('ui_animated_text_damage_chain')` each frame (cheap `drawImage` blits — no text rasterization); if the sheet isn't loaded yet `_drawBlock` no-ops. The block stays composed through finalize + fly (`_drawBlock` is shared by `_renderCentered` and `_renderFlying`); the whole block pops (`easeOutBack`/`FINAL_BACK`) then flies to the portrait together. Same externally-managed contract as `FloatingTextEffect` (`update(dt)`/`render(ctx)`/`done`); lives in BattleScene `_floatingEffects`. Managed per-side by BattleScene `_damageCounters` (`_addDamageToCounter` adds to the live counter or creates a fresh one when the previous is finalizing/done; `onImpact` is left unwired — the portrait impact deliberately triggers NO extra screen shake); BattleScene feeds it the info-column (`setCenter`) + receiver-portrait (`setTarget`) anchors + the `resolving` hint each frame (held alive only while its side is the one being attacked — `resolving && activeSide !== side` — so a cascade stays ONE counter). All feel tunables are top-of-file consts. See decision #41.

#### ManaStreamEffect — [`src/js/ui/ManaStreamEffect.js`](../../src/js/ui/ManaStreamEffect.js)

**Thin whispy mana stream from matched tiles to a mana orb.** When a mana match resolves, a few thin glowing color-tinted "wisps" fly from the matched board cells and converge on the matching mana counter orb in the active side's pane, each along a gently bowed path with a 2-pass (wide-soft + thin-bright) trailing streak + bright head, additive `'lighter'` glow, staggered for a flowing look, fading as they land. An optional `onArrive` callback fires as the leading wisps reach the orb (BattleScene wires it to `CharacterInfoPane.pulseManaOrb` for a synced orb bobble). Same externally-managed contract as `FloatingTextEffect`; lives in `_floatingEffects`. **Mobile-tuned for cheap drawing** (many wisps can be on screen at once): NO `ctx.shadowBlur` (the biggest mobile canvas cost — additive blend supplies the glow), the head glow is a per-color sprite baked ONCE into a module cache and drawn via `drawImage` (no per-frame `createRadialGradient` allocation), and the path is walked with reusable scratch points (zero per-frame allocation). Spawned by `BattleScene._spawnManaStream` from `getState().matchTextTriggers` (now carrying all match `positions`) for mana-color matches only (skull/inert grant no mana → no stream). Feel tunables are ctor config. See decision #41.

#### TileParticleEffect — [`src/js/ui/TileParticleEffect.js`](../../src/js/ui/TileParticleEffect.js)

Particle burst for tile destruction and conversion effects. **Mobile-tuned (2026-07):** the glow/core/flash radial gradients are baked ONCE per tile color into small module-cached sprites (`_getSprite`) and drawn via scaled `drawImage` + `globalAlpha` — the old 2×`createRadialGradient` per particle per frame was the dominant cascade render cost (100+ live particles in a big cascade). Alpha stops scale linearly, so the look is pixel-equivalent.

#### HarvestTendrilEffect — [`src/js/ui/HarvestTendrilEffect.js`](../../src/js/ui/HarvestTendrilEffect.js)

**Thrall-harvest energy-tendril animation.** Draws a persistent, writhing red **energy connection** that spans each source board cell ↔ a single target point (a portrait) for its whole life — a bundle of independently-phased strands (straight source→target line + a perpendicular, time-scrolling wave enveloped to 0 at both ends so it stays anchored to the tile and the portrait), with bright pulses flowing along each strand toward the target. Phases FORM (connection grows out) → HOLD (full connection writhes) → FADE. Spawned by `BattleScene._spawnHarvestTendrils` from `getState().harvestEvents` (Usurper's Heart): red tendrils stay connected from each harvested Thrall tile to the boss portrait. Same externally-managed effect contract as `FloatingTextEffect` (`update(dt)`/`render(ctx)`/`done`); lives in `_floatingEffects`. All feel tunables (color, **coreColor** = hot inner-core/pulse/flare color, waveCount, amplitude, flowSpeed, strands, pulses, durations) are ctor config. **Mobile-tuned (2026-07, same rationale as ManaStreamEffect):** NO `ctx.shadowBlur` (the old blur-14 on every strand stroke was the harvest frame-drop; a wide faint halo stroke + additive blend replaces it), pulse/anchor/flare glows are baked per color pair into module-cached sprites (`_bakeGlow`) instead of per-frame `createRadialGradient`, and the strand polyline uses a reusable scratch array (zero per-frame allocation). **Reused (continuous mode):** `config.continuous=true` makes the connection never fade or complete (`_alpha` stays 1, never sets `done`) — caller drops the instance to end it. `render` MULTIPLIES the host `globalAlpha` (not overwrites) so an external fade carries through. [`SkillWeaveScene`](../../src/js/scenes/SkillWeaveScene.js) repurposes this for the sustained purple crucible orb→center energy beams.

#### BloodSplashEffect — [`src/js/ui/BloodSplashEffect.js`](../../src/js/ui/BloodSplashEffect.js)

#### HintCursorEffect — [`src/js/ui/HintCursorEffect.js`](../../src/js/ui/HintCursorEffect.js)

**Animated gauntlet pointer for the hint system** (the `ui_hint_cursor` art — fingertip hotspot `TIP_FRAC` top-left). ### Tooltips & keyword text

#### Tooltip — [`src/js/ui/Tooltip.js`](../../src/js/ui/Tooltip.js)

**Reusable floating tooltip visual.** Background asset `tooltip_panel` + optional bold `title` stacked above a centered, word-wrapped body — the body is a [`KeywordText`](../../src/js/ui/KeywordText.js) so `[[Keyword]]` markup in the text renders as colored, bracket-free spans (plain text with no markup behaves exactly as before). When `title` is set the title + `titleGap` + body are measured as one block and vertically centered inside the padded inner area (title sits directly above the body, both center-aligned horizontally); when empty, the body fills the whole inner area centered (legacy behavior). Aspect ratio is preserved — only width (or `scale` multiplier) is configurable; height is derived as width / native aspect so the art never stretches. Driven externally by `TooltipManager` (not added as a child of any container). `setOptions({text, title, scale, width, padding, fontSize, lineHeight, color, titleFontSize, titleColor, titleBold, titleGap, autoSize})` + `setPosition(x, y)` + `render(ctx)`. **autoSize mode:** the panel WIDTH grows (up to `AUTO_SIZE_MAX_WIDTH`) until title + wrapped body fit the aspect-derived height — used by the skill-button "?" tooltips so a long skill description fits. **`resetStyleDefaults()` resets ALL per-show options (colors AND width/scale/padding/fontSize/autoSize)** — setOptions does partial updates, so without the full reset one source's sizing would bleed into every later tooltip (the "all tooltips became huge" bug).

#### KeywordText — [`src/js/ui/KeywordText.js`](../../src/js/ui/KeywordText.js)

**Inline keyword text element.** Renders a string containing `[[Keyword]]` markup as normal text with colored, interactive keyword spans (brackets never shown; the visible text is the keyword's `label`). Also renders `<<n>>` **dynamic-value** segments (parsed by keywordParser as `type:'dynamic'`) in `KEYWORD_DYNAMIC_COLOR` — colored but NOT a hoverable span; used for live computed damage (see decision #34). Mirrors the subset of `UIText`'s API used by `Tooltip`/`RewardOptionPanel` (`setStyle`/`measureText`/`renderSelf`/`rect`) so it's a drop-in for any description body; with no markup it behaves like a plain centered label. Keyword-aware word-wrapping; optional **`maxLines`** style caps the wrapped line count (overflow lines drop and a trailing ellipsis is drawn — the SkillButton 2-line description; `get truncated` reports it). Records each keyword span's on-screen rect (`getKeywordRects()`) for direct-hover wiring. Colors/definitions come from [`keywordDefinitions.js`](../../src/js/data/keywordDefinitions.js); unresolved keywords render in a fallback color (no crash). Used as the body of `Tooltip` and the description of `RewardOptionPanel`.

#### TooltipManager — [`src/js/systems/TooltipManager.js`](../../src/js/systems/TooltipManager.js)

**Reusable tooltip system + keyword tooltip chains.** Owns a parent `Tooltip`, a pool of child `Tooltip`s, and a list of `(element, options)` attachments. Resolves hover vs touch-hold input by reading `input.mouseDown` (set BEFORE mousemove fires on touchstart, so touches always look "pressed" and skip the hover path). Hover shows on mouseover/hides on mouseout. Touch-hold uses `TOOLTIP_TOUCH_HOLD_MS` (350ms) timer started on mousedown; cancelled by movement beyond `TOOLTIP_TOUCH_MOVE_CANCEL_PX` (10px) so swipes still work. Position picks the side opposite to the parent relative to screen center (horizontal preferred, vertical fallback if it would clip), then clamps to the design viewport with `TOOLTIP_EDGE_MARGIN` (generalized into `_positionTooltip(tooltip, sourceRect, opts)` so any rect can be a source). **Keyword tooltip chains:** when a shown tooltip's title+body contains `[[Keyword]]` markup, `_buildChain` calls [`buildTooltipChain`](../../src/js/systems/keywordParser.js) to resolve an ordered, de-duplicated list of keyword definitions (BFS over keyword descriptions, capped at `MAX_TOOLTIP_CHAIN_DEPTH` and protected against recursion by a visited-id set), then renders one child `Tooltip` per link. The **parent** is placed beside its source element (toward screen center); the **chain links stack as a vertical column** anchored to the parent's left edge, each `KEYWORD_TOOLTIP_CHAIN_GAP` below the previous, and the whole column is shifted to stay on screen. (A single column is used deliberately — an earlier "each link relative to previous, re-pick side at center" scheme made links ping-pong between two columns and overdraw each other, so only the last 1–2 tooltips were visible.) Hiding the parent clears the whole chain. Chaining is on by default; disable globally via `setKeywordChainEnabled(false)` or per-attachment via `options.keywordChain === false` / `options.maxChainDepth`. **Inline keyword spans:** `attachKeywordSource(keywordTextEl, opts)` registers a [`KeywordText`](../../src/js/ui/KeywordText.js) so each of its `[[keyword]]` spans (from `getKeywordRects()`) becomes its own hoverable/touchable tooltip source — hovering a keyword IN any description shows that keyword's definition (+ its own chain). Synthetic span attachments are cached per element+keywordId for stable hover identity; the active span's rect is refreshed each frame and auto-hidden if the span disappears. `clearKeywordSources()` drops them without touching regular attachments (used on skill rebuild). API: `attach(el, opts)`, `detach(el)`, `attachKeywordSource(el, opts)`, `detachKeywordSource(el)`, `clearKeywordSources()`, `clear()`, `setEnabled(bool)`, `setKeywordChainEnabled(bool)`, `onMouseMove/Down/Up`, `update(dt)`, `render(ctx)`.
