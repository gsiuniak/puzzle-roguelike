# Decision #45 — The in-game hint system plays the TRAINED CHAMPION (2026-07-08): full-action suggestions via the promoted formula policy, presented with a gauntlet cursor + banner.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**The in-game hint system plays the TRAINED CHAMPION (2026-07-08): full-action suggestions via the promoted formula policy, presented with a gauntlet cursor + banner.** The "?" hint button no longer asks MoveAdvisor for a swap — it asks the ~45%-run-survival champion formula policy for the best ACTION (cast, with its best target, or swap) and stages a guided presentation. Architecture:
- **One policy, one source.** `sim/toolbench/formula.mjs` was PROMOTED to [`src/js/game/ai/formulaPolicy.js`](../../src/js/game/ai/formulaPolicy.js) (browser-safe, unchanged logic) and the sim file became a re-export shim — the enemyScaling.js pattern (shared code lives in src; sim imports it). The tracked champion weights moved to [`src/assets/data/formula-champion.json`](../../src/assets/data/formula-champion.json) (a game asset: shipped by the Vite build, fetched per session by [`ai/hintWeights.js`](../../src/js/game/ai/hintWeights.js) `loadHintWeights()`, `{}`→defaults fallback); `CHAMPION_WEIGHTS_PATH`, `weights-node.mjs`, the bench Hard AI, and `reports/promote-champion.mjs` all point at the new location — retraining + promoting a new champion upgrades the game's hints with zero game-code changes.
- **The seam is a facade, not a sim battle.** The policy's input contract is tiny (`{ board, p, e, other(), canAfford(), _hasStatus() }` + combatant scalars/mana/skills/statuses/dynAtkRules — documented in the module header). [`BattleController._makeHintFacade`](../../src/js/game/BattleController.js) satisfies it from LIVE battle state (board by reference — the policy only clones; combatants as snapshots, `_attackPerManaRules`→`dynAtkRules`), so hints see the REAL board (locks, wilds, disease) and REAL stats (floor scaling, relic modifiers, statuses). `getSuggestedAction({weights, chainDepth})` gates on PLAYER_TURN, runs the policy (deterministic — no RNG, no `withSeededRandom` hazard, a few ms), and `_describeSuggestedAction` enriches the raw action with `targetCells` (via the exported `targetPositions`) + a human `description` derived from the refill-off `settleBoard` outcome (a guaranteed lower bound — the text never over-promises). Targeted skills the policy prices flatly (lock_color) return `needsManualTarget` and a "pick a target tile" description.
- **Presentation (BattleScene + [`HintCursorEffect`](../../src/js/ui/HintCursorEffect.js), the `ui_hint_cursor` gauntlet art):** swap → existing gold two-cell outline + arrow, cursor "drags" A→B; cast → card auto-scrolled into view (`SkillsPane.scrollToSkill`) + cursor taps it, then glides to the target cell with a translucent gold ghost over every hit cell; a top-center nameplate banner shows the description. Cursor waypoints recompute EVERY FRAME from live layout (scroll-proof); everything fades/clears on the shared hint lifecycle (early-clear the moment the player acts). The idle board GLINT deliberately does NOT use the champion suggestion — it keeps the old simple MoveAdvisor swap (`_getSuggestedMoveCached`, its own per-turn cache), so the periodic nudge never goes dark when the champion would rather cast.
- **Caveat:** `getSuggestedAction` suggests from `playerState.skills` (the EQUIPPED loadout) — never an unequipped skill. Cache invalidation matches the old hint (state leaves PLAYER_TURN, skill cast, loadout change).
