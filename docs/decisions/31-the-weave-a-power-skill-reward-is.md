# Decision #31 — The "Weave a Power" skill reward is a layered-RNG tag draft + a synthesis step — all randomness/data lives outside the scene.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**The "Weave a Power" skill reward is a layered-RNG tag draft + a synthesis step — all randomness/data lives outside the scene.** [`SkillWeaveScene`](../../src/js/scenes/SkillWeaveScene.js) is a full-canvas scene that replaces the relic-style "pick 1 of 3 finished options" reward for **skills** with a variable-length keyword draft, then synthesizes the chosen "bag" of tags into a skill. It is fully decoupled across three data modules:
- **RNG config** ([`weaveConfig.js`](../../src/js/data/weaveConfig.js)) owns every tunable table (tag-rarity weights, rounds-per-weave, tags-per-round, hidden per-tag value tables). All are **relative weights** normalized at pick time, so any single number tweaks in isolation (a table summing to 110, like the rounds weights, behaves fine). The scene rolls its shape via `_rollWeavePlan` → `{rounds, tagCounts}`.
- **Catalog/draw** ([`skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js)) owns the id-keyed tag catalog (each tag has a `rarity` + `category`) and `drawTagsForRound({roundIndex, chosen, count})`: a **rarity-weighted draw from one global pool**, no repeats, with a soft guarantee that round 0 includes ≥1 ACTION tag (so every bag has a verb). The old positional `[action, element, shape]` grammar (`ACTION_RULES`/`getValidTagsForStep`) is **gone** — validity is no longer enforced at draft time; the synthesizer makes sense of whatever bag results. Extend by adding a catalog entry (no scene change).
- **Synthesis** ([`skillSynthesizer.js`](../../src/js/data/skillSynthesizer.js)) — `synthesize(recipe)` is the future "bag → real skill" engine; today a **STUB** that groups tags by category + rolls hidden values and emits no real skill. The deeper rules the user wants (special combos, "not every tag is used", premade-spell overrides) attach here, not in the scene.
- **Draft state** is a `_recipe` (committed tag ids) + a `_steps` stack of `{options, picked?}` per step (`picked` = the committed option index, used so Back can fly the tag back to the right plaque). **Clicking a tag commits it immediately** (`_pickOption` pushes onto `_recipe` + builds the next step); **Back** pops `_recipe` and truncates `_steps` to `_recipe.length + 1`, restoring the previous step's exact options (never discarded). **Confirm** is gated on `_complete` (recipe full) and is the sole "resolve into a skill" action — there is no per-tag selection state; hover alone provides the grow+glow affordance.
- **Animation layer** (`_anim`, advanced in `update`→`_advanceAnim`; input is locked while non-null via `_animBusy`). The draft model is mutated UP-FRONT by `_pickOption`/`_back` (so the slot + next-step data the animation reads already exist), then a purely-visual animation plays: **intro** (tags fan/grow out from a central focal point — the centroid of their rest rects — to position, staggered; on enter + after every commit/back), **commit** (clicked tag flies + pops into its recipe slot while the unpicked tags fade out → then the next step's intro), **back** (two phases: the current step's tags collapse back to the focal point reverse-intro, then the popped recipe tag flies out of its slot back to its plaque while the previous step's siblings fade in). All option drawing routes through `_drawOptionTransformed` (scale-about-center + reposition + alpha); the travelling tag is drawn on top of the recipe in `_renderFlyingTag`; slot content during animations is overridden in `_renderRecipe` (suppress the static tag for the slot being flown into/out of). Button visual-enabled deliberately ignores `_animBusy` so they don't flicker dim mid-animation. Timings/feel are all top-of-file constants (`INTRO_*`, `COMMIT_*`, `BACK_*`, `FLY_POP`).
- **Variable layout.** The recipe holds 2–4 slots (= rounds) that **shrink to fit** the rolled count inside a height-budgeted container (`_recipeRect` caps height at `RECIPE_MAX_H` so the wider container art can't collide with the buttons; a **4-slot recipe swaps to the wider `ui_skill_weave_container_wide` art** via `_recipeContainerKey`); options arrange as 2/3-up fans or a 4-up grid (`_optionAnchors`, narrower plaques at 4 via `OPTION_W_BY_COUNT`). Option plaque art is **rarity-suffixed** (`_optionAssetForTag` → `ui_skill_weave_option_container_<rarity>`, common = base) with a rarity-tinted hover glow.
- **Entry/exit mirrors the battle contract.** MapScene routes the `training` node via `_transitionToSkillWeave(node)` (serializes traversal into `_savedTraversalState`, `configure({onComplete, returnScene})`, `fadeToScene`). `onComplete` (payload `{recipe, synthesis}`) calls the SAME `_handleBattleComplete({result, nodeId})` battle uses, so on return `MapScene.onEnter` completes the node + reveals the next depth identically.
- **The reward is REAL:** `_finishWeave()` calls `synthesize()` (the rule engine — see the skillSynthesizer row in §4.7) which emits a full castable skill (effects + hidden-rolled magnitudes + a CONTINUOUS power-scaled mana cost SPLIT across the woven colors + generated name/description with `[[keyword]]` markup), attaches the procedural icon (`skill.icon = icon.assetKey`), and shows the skill summary in the RESULT phase. On Continue, MapScene's `onComplete` pushes the skill onto **`runState.skills`** (full objects — woven skills exist in no catalog) and `createPlayerBattleState` appends them to the character's skills every subsequent battle. Redundant/incompatible picks are a **CHOICE-DRIVEN downside**: they deterministically contribute nothing and are surfaced via `synthesis.wastedReasons` (shown as "Wasted X — <reason>" on the result screen) so a weak weave reads as avoidable, not a dice roll. (The old "weave surges" injection is gone; `synthesis.injectedTags` is retained but empty.) All layout/visual tunables are named constants atop the scene; the skill_weave assets (incl. the 3 rarity option containers) are registered in [`main.js` ASSET_MAP](../../src/js/main.js#L35) and the tag icon falls back to the gold-flame placeholder until per-tag art exists.
