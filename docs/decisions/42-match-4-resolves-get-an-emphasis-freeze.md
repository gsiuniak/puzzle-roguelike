# Decision #42 — Match-4+ resolves get an emphasis "freeze" beat + board-darken flourish.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Match-4+ resolves get an emphasis "freeze" beat + board-darken flourish.** When a 4+ match GRANTS AN EXTRA TURN, the board holds on the matched tiles for a brief configurable moment before cascades continue — not a full pause, just enough that the brain registers "something important happened".
- **Controller** ([`BattleController`](../../src/js/game/BattleController.js)). In `_enterShowMatch`, when the extra-turn condition is met (`analysis.extraTurnTrigger && !_resumeTurnAfterResolve && _canGainExtraTurn` — the SAME gate that sets `_extraTurnEarned`, so turn-start setup cascades are excluded), it collects the positions of every `count >= 4` match into **`_match4Flourish`** `{ cells, color, side, durationMs }` and sets **`_match4FreezeMs`** to a per-side freeze. The SHOW_MATCH phase timer holds for `phaseMs + _match4FreezeMs` (the freeze is EXTRA hold on top of the normal ~400ms highlight), so `_doRemove` (and thus the cascade) waits out the beat. Freeze durations are the top-of-file **`MATCH4_FREEZE_MS`** (`{ player: 115, enemy: 75 }` ms — presentation timing, NOT speed-scaled; player's beat is longer). Both fields are cleared in `_doRemove`/`_beginResolving` and reset each `_enterShowMatch`; `_match4Flourish` is surfaced via `getState()`.
- **Global hit-stop.** [`BattleController.isHitStopActive()`](../../src/js/game/BattleController.js) is true for the first `_match4FreezeMs` of the flourish's SHOW_MATCH. [`BattleScene.update`](../../src/js/ui/BattleScene.js) checks it right after `updateFromController()` and, while active, **freezes EVERYTHING** — it early-returns after updating ONLY `this._board` (so the flourish keeps playing), skipping `super.update` (panes/portraits/relic bars/attack animation), all `_floatingEffects` (damage counters, floating text, mana streams, turn-announcement images), `_particleEffects`, and `_screenShake`. The controller's phase timer still advances (it ran before the check), so the freeze self-terminates and the scene resumes from exactly where it held. (Live `<video>` portraits keep decoding — a ~120ms drift is negligible — everything update-driven stops.) **Audio freezes too:** on the freeze's leading edge BattleScene calls `AudioManager.pauseSfxExcept(['sfx_match4_flourish', 'sfx_match4_flourish_enemy'])` (every in-flight SFX pauses mid-buffer; music untouched) and on the trailing edge `resumeFrozenSfx()` resumes them in place (edge-tracked via `_sfxHitStopFrozen`; safety-resumed in `onExit`). The **flourish SFX itself is PER-SIDE** (BattleScene branches on `state.match4Flourish.side`): the player plays `sfx_match4_flourish` (the packed `match_4_special` clip in the SFX sprite sheet by default; the `USE_TMP_MATCH4_FLOURISH` const in [`SoundConfig.js`](../../src/js/audio/SoundConfig.js) quick-switches it back to the old temporary standalone file `assets/audio/sfx/tmp/tmp_match4.mp3`), the enemy plays **`sfx_match4_flourish_enemy`** (always the standalone `assets/audio/sfx/tmp/tmp_match4_enemy.mp3`, not gated by that const). It fires once per flourish (new `state.match4Flourish` reference → `_lastMatch4Flourish`) the frame the beat starts, and both keys are excluded from the freeze. **Skill-cast sounds are pre-checked and HELD when the cast will flourish:** in `_castSkill`, a cast that enters a cascade runs [`_cascadeWillFlourish()`](../../src/js/game/BattleController.js) — true if the first step already flourished (`_match4Flourish` set synchronously — the convert/create case) OR a deterministic settle simulation ([`BoardSimulator.resolveBoardInPlace`](../../src/js/game/BoardSimulator.js), refill OFF, on a clone with the in-flight step's tiles removed; a destroy-entered cascade already carries its holes since it starts at REMOVE with `_analysis` null) reaches a 4+ (`extraTurn`), gated by the same `_canGainExtraTurn`/`_resumeTurnAfterResolve` checks as the flourish. When true, the pending skill sound moves to `_heldSkillSound` and is released back into `_pendingSkillSound` the frame the hit-stop ends (`update()` — so the flourish SFX plays alone during the freeze, then the skill sound follows), with safety releases at `_finishResolving` (mispredict — refill interfered with a deep predicted step) and on GAME_OVER. Refill can only ADD tiles, so a predicted 4+ always materializes; a refill-CREATED 4+ isn't predicted — the sound plays normally and the hit-stop pause/resume covers it.
- **Board render** ([`BoardPlaceholder._renderMatch4Flourish`](../../src/js/ui/BoardPlaceholder.js)). BattleScene passes `state.match4Flourish` to the board each frame. The board self-times off `_flourishTime` (advanced in `update`, reset when the flourish reference changes). During the beat it **darkens the whole board** (semi-transparent black), lays a soft warm **additive radial bloom** behind the matched tiles (overlapping per-cell radials + a hot white core merge into one continuous glow across the group), then **redraws the matched 4+ tiles ON TOP** with the tile ART additively brightened (sprite-over-sprite, so the glow follows the tile SHAPE, not a boxy square); wild frames follow. The tiles **POP by scaling the whole matched group about its shared centroid** (each tile grows AND shifts outward proportionally, riding an easeOutBack overshoot), so the cluster expands as one rigid unit and tiles NEVER overlap each other regardless of `growScale` — they only bulge over the surrounding darkened non-matched tiles. The darken/bloom/brighten/pop ride a fade-in → hold → fade-out **envelope entirely within the freeze window**, so it's a punch (not a lingering dim) and the normal highlighted board resumes for the rest of SHOW_MATCH. Applies to BOTH sides (enemy uses the shorter beat). Look tunables: **`MATCH4_FLOURISH`** (darken, bloom radius/alpha, core, tile brighten, optional `growScale`) + **`MATCH4_GLOW_COLORS`** (per-type glow color, as `"r,g,b"`). **EXPERIMENTAL "Sekiro parry" flash** (`MATCH4_FLOURISH.parryFlash`, `enabled` flag — may be disabled): an instant near-white flare + expanding thinning shockwave ring + a fan of tapered glint streaks bursting from the matched group's centroid (`_renderParryFlash`, drawn topmost in the 'tiles' phase over the popped tiles, additive, no shadowBlur); it runs its own sharper curve (brightest on frame 1, dissipated by `spanFrac` of the beat) instead of the darken envelope so it reads as a deflect-spark. **Per-side variant:** the `parryFlash.enemy` sub-object is merged over the base config when `match4Flourish.side === 'enemy'` — slightly toned down + shifted red (any parryFlash field can be overridden there; `centerColor` is the flare's hottest center stop, default white).
