# Decision #32 — Status effects (buffs/debuffs) are a general, data-driven system; their durations tick by TURN CYCLE.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Status effects (buffs/debuffs) are a general, data-driven system; their durations tick by TURN CYCLE.** The roster is the pure DATA catalog [`statusEffects.js`](../../src/js/data/statusEffects.js) (9 statuses: 6 debuffs, 3 buffs); ALL battle behavior lives in [`BattleController`](../../src/js/game/BattleController.js). The old one-off turn-scoped debuffs (`_silencedTurns`, `_attackOverride`) were **removed and unified** into this system — Silence is the `silenced` status and Exsanguinate's attack-pin is the `crippled` status (`attackValue`, default 1).
- **State:** each combatant carries `statuses: []` (added in `_cloneState`, runtime-only). An entry is `{ id, kind, turns, _armed, sourceSide, attackValue?, savedAttack?, tickDamage? }`.
- **Turn-cycle timing (the core rule):** a status lasts N cycles of the AFFECTED side (a cycle = that side holding control once). Ticked at the **START of the affected side's turn** in `_tickStatusesAtTurnStart` (called from `_completeTurnIntro`, NOT `_endTurn`). Each carries `_armed`, set at apply: SELF-applied (target IS the active side) → `_armed=true` (current turn is cycle 1, underway); OPPONENT-applied → `_armed=false` (cycle 1 begins at their next turn start). Per tick: `if (_armed) turns--; else _armed=true;` then remove when `turns<=0` (before any per-turn effect), else apply per-turn effects (Bleed). **"Active" for every game-logic check = the status is PRESENT in the list** (`_hasStatus`); durations only control persistence. Extra turns bypass `_completeTurnIntro`, so statuses do NOT re-tick mid extra-turn chain (correct — control was never lost). Bleed at turn start can be lethal, so `_completeTurnIntro` re-checks game over after the tick.
- **API / apply:** `_applyStatus(targetState, id, { turns, attackValue }, applierSide)` (refresh keeps the longer duration + original saved data); `_hasStatus`/`_getStatus`/`_removeStatus`; `_canGainMana(side)` / `_canGainExtraTurn(side)`. Crippled snapshots `savedAttack` + pins attack (frozen against `_recomputeDynamicAttack`, re-pinned each frame by `_enforceStatusAttack`, restored on expiry). Bleed snapshots `tickDamage = ceil(applier.attack/2)` at apply.
- **Per-status checkpoints:** Silence → `tryPlayerSkill` + `_doEnemyTurn` (skip skill casts, fall to `_doEnemySwap`); Cripple → attack pin (above); Enfeeble → `_canGainMana` gates the active-side mana credit in `_doRemove` + `_executeDestroyTiles`; Frozen → `_canGainExtraTurn` gates the extra-turn grants (`_enterShowMatch` 5+ match, the `extra_turn` skill effect, the passive `onExtraTurn` callback); Brittle/Intangible/Berserk → all in **`_applyDamage(target, amount, opts)`** (opts.attackerSide for Bleed). A Berserk attacker deals ×2 and ignores the target's defensive statuses; otherwise Brittle ×1.5 then Intangible clamps to 1 (wins); a Berserk target always takes ×2. **Berserk is a stub — no content applies it yet; its multipliers are tunable.** **(Barrier is no longer a status — it's a numeric shield pool absorbed in `MatchResolver.applyDamage` AFTER this mitigation, alongside armor; see decision #38.)**
- **Skill application:** the `apply_status` effect type (`{ effectType:'apply_status', applyStatus:{ id, target:'self'\|'opponent', turns, attackValue? } }`) is the general way to apply any status from a skill (resolved in `_resolveEffect` → `_applyStatus`). The legacy `silence`/`set_attack` effect types still work as thin aliases.
- **UI:** [`CharacterInfoPane`](../../src/js/ui/CharacterInfoPane.js) draws overlays over the portrait (`_renderStatusOverlays`, reading `state.statuses` via `updateFromState`). Display = "one big + count": the most-recent buff (tall crest) and most-recent debuff (wide crossed-blade X) render as large overlays at SEPARATELY tunable anchors (`STATUS_BUFF_*` / `STATUS_DEBUFF_*` — the two art shapes differ), plus a centered row of mini-badges for additional statuses and an optional remaining-turn count. Art from `ui_spritesheet_status_effects`. Buff/debuff hover-tooltips on the overlays are NOT wired yet (overlays are drawn manually, not registered UI elements).
