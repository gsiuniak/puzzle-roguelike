# Decision #29 — Descriptions support data-driven inline keywords with chained tooltips.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Descriptions support data-driven inline keywords with chained tooltips.** Any UI description string may embed `[[Keyword]]` markup. The pipeline is fully reusable and lives outside any individual renderer:
- **Definitions** ([`keywordDefinitions.js`](../../src/js/data/keywordDefinitions.js)) — centralized `{ id, label, description }` catalog keyed by normalized id (+ `KEYWORD_ALIASES`). Single place to add/tune keywords. **One shared color (`KEYWORD_COLOR`) for all keywords** — keyword styling is intentionally uniform, not per-keyword.
- **Parsing** ([`keywordParser.js`](../../src/js/systems/keywordParser.js)) — `parseKeywordText` turns markup into text/keyword segments; the `[[ ]]` brackets are never shown (the visible text is the keyword's `label`). Unknown keywords fail gracefully (fallback color + one-time dev warning, no crash).
- **Rendering** ([`KeywordText`](../../src/js/ui/KeywordText.js)) — a `UIText`-compatible element that draws colored, keyword-aware wrapped text. It is the body of `Tooltip` and the description element of `RewardOptionPanel`, `SkillButton`, and the CharacterSelect skill/relic/character blocks — so keyword coloring + bracket stripping happen **anywhere a description renders**, with no per-renderer keyword code.
- **Inline keyword tooltips ("anywhere")** — any scene with a `TooltipManager` can call `attachKeywordSource(keywordTextEl, opts)` to make a description's individual keyword spans hoverable. Wired today in **CharacterSelectScene** (`_registerKeywordTooltips` — skill/relic/character descriptions; the scene owns its own `TooltipManager`, re-registering on every selection change). **BattleScene's skill cards show their full descriptions directly** ([`SkillsPane`](../../src/js/ui/SkillsPane.js) — auto-height legacy cards), so there is no full-skill tooltip; `BattleScene._registerSkillTooltips` registers every card's description `KeywordText` as a keyword source — hovering a colored `[[keyword]]` on any card shows its definition + chain.
- **Chained tooltips** ([`TooltipManager`](../../src/js/systems/TooltipManager.js)) — hovering/touch-holding a relic (or any keyword span) shows the parent tooltip AND auto-spawns a chain of child keyword tooltips (one per keyword in the parent's text, then keywords nested inside those, BFS). The parent sits beside its source (toward center); the chain links stack as a **vertical column** below the parent, shifted to stay on screen (a single column avoids the overlap/ping-pong a per-link side-flip caused). Recursion is bounded by `MAX_TOOLTIP_CHAIN_DEPTH` + a visited-id set; spacing is `KEYWORD_TOOLTIP_CHAIN_GAP`. Hiding the parent hides the whole chain. **Existing tooltip behavior is unchanged for keyword-free descriptions** — chaining is purely additive. Enabled by default; opt out per-attachment with `options.keywordChain === false`.
