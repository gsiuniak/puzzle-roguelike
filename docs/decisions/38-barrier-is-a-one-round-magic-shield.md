# Decision #38 — Barrier is a one-round MAGIC shield (an armor-like numeric pool), NOT a status.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Barrier is a one-round MAGIC shield (an armor-like numeric pool), NOT a status.** Barrier was reworked from a buff status (which blocked one skull-damage instance and drew a portrait overlay) into a temporary-HP pool that behaves like armor but scales with Magic and expires after a round. It reuses the armor machinery throughout:
- **State.** Each combatant carries a numeric `state.barrier` (added in [`BattleController._cloneState`](../../src/js/game/BattleController.js), runtime-only, always starts at 0; reset on `_transformInto`). It is NO LONGER in [`statusEffects.js`](../../src/js/data/statusEffects.js) (removed from the catalog) and never appears in `state.statuses` (so [`CharacterInfoPane._renderStatusOverlays`](../../src/js/ui/CharacterInfoPane.js) never draws a barrier overlay — requirement #3). The `[[barrier]]` keyword stays (description updated); the `buff_barrier` sprite is now unused.
- **Absorption.** [`MatchResolver.applyDamage`](../../src/js/game/MatchResolver.js) now resolves **barrier → armor → block → HP**: barrier absorbs FIRST (it's the expiring resource, so spending it before permanent armor preserves the armor). Like armor, barrier-absorbed damage still counts toward `actualDamage` (only `block` fully negates); the return adds `barrierDamage`. The OLD per-instance skull-block in [`BattleController._applyDamage`](../../src/js/game/BattleController.js) was REMOVED — barrier now absorbs ALL damage types, after the Brittle/Intangible/Berserk status mitigation (which still runs before the resolver). `opts.isSkull` is now unused by `_applyDamage` (callers still pass it harmlessly).
- **Scaling (requirement #1).** Barrier scales with **Magic twice as effectively as armor scales with Attack**: armor uses `_33` (Attack ×1/3); barrier uses the new **`_66`** preset (Magic ×2/3) in [`scalingConfig.js`](../../src/js/data/scalingConfig.js) `DAMAGE_SCALING_PRESETS`. `scalablePayload` recognizes the `barrier` effect so `<<n>>` descriptions resolve the live Magic-scaled value.
- **Effect type.** New **`barrier`** effect (`{ effectType:'barrier', barrier:{ amount, scaling } }`) in [`MatchResolver` SKILL_EFFECT_TYPES](../../src/js/game/MatchResolver.js), [`BattleController._resolveEffect`](../../src/js/game/BattleController.js) (skill path: `src.barrier += amount + scaledBonus`, floating 'barrier' stat), and [`EffectResolver`](../../src/js/systems/EffectResolver.js) (relic/passive path, mirrors armor). Expiry is owned by BattleController regardless of how it's granted.
- **Expiry (requirement #2).** Barrier lasts exactly one round: it's granted mid-turn, survives the owner's turn + the opponent's turn, and is cleared at the owner's NEXT turn start in [`_completeTurnIntro`](../../src/js/game/BattleController.js) (BEFORE the onTurnStart dispatch). Because grants happen after that turn's intro and extra turns bypass `_completeTurnIntro`, no `_armed` flag is needed — a plain "clear the side's barrier at its turn start" gives the correct one-round lifetime ("gain barrier → enemy turn → lose remaining barrier at your next turn").
- **Rendering (requirement #4).** Instead of a portrait overlay, barrier shows as a "temporary HP" bar overlay EXACTLY like armor but **semi-transparent purple** ([`UIProgressBar`](../../src/js/ui/UIProgressBar.js) `barrierValue`/`barrierColor`/`barrierFillAlpha`/`barrierOverlayAlpha`), stacked OUTWARD beyond armor (health | armor | barrier) via one generalized stacked-shield routine. [`CharacterInfoPane`](../../src/js/ui/CharacterInfoPane.js) sets `healthBar.barrierValue = state.barrier` and `_renderShieldBadges` (renamed from `_renderArmorBadge`) draws the armor badge (`icon_block`, blue) then a barrier badge using the **`icon_barrier`** sprite from `ui_spritesheet_character_pane` (purple) beside the HP label. Barrier gains float a purple "+N" ([`BattleScene`](../../src/js/ui/BattleScene.js) `STAT_TEXT_STYLE.barrier`).
- **Synthesis.** The weave `barrier` tag moved from a STATUS tag to an **ACTION** tag in [`skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js); [`skillSynthesizer.js`](../../src/js/data/skillSynthesizer.js) `emitBarrier` (armor-like, `_66` Magic scaling, `Gain <<n>> [[barrier]]`) replaces the old apply_status path (barrier removed from `STATUS_TAG_TO_ID`/`SELF_STATUS_TAGS`); its magnitude table in [`weaveConfig.js`](../../src/js/data/weaveConfig.js) `TAG_VALUE_TABLES` is now armor-like (was turn durations). `greater` amplifies it like any magnitude verb. Icon priority moved to the action range in [`spellIconRecipe.js`](../../src/js/icons/spellIconRecipe.js) (`foreground_barrier` sprite exists).
