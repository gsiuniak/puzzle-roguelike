# Decision #37 — Mid-battle enemy TRANSFORM is a general, data-driven identity swap (the Sanguine Phoenix engine).

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Mid-battle enemy TRANSFORM is a general, data-driven identity swap (the Sanguine Phoenix engine).** An enemy can become a DIFFERENT enemy mid-fight without bespoke boss code, reusing the relic/trigger/board-effect machinery:
- **Forms.** An enemy that can transform lists the alternate enemy ids in `transformForms: [...]`. [`MapScene._transitionToBattle`](../../src/js/scenes/MapScene.js) BFS-gathers the reachable set (including the primary so a form can revert to a full-life primary) and resolves EACH via the new shared [`MapScene._resolveEnemyBattleData(def, depth)`](../../src/js/scenes/MapScene.js) (deep-clone + the same floor HP/attack scaling + skill/relic resolve), then attaches the `{ id → resolvedData }` map as `enemyData._forms`. [`BattleController`](../../src/js/game/BattleController.js) reads it into `this._enemyForms`. Normal enemies have no `transformForms`, so `_forms` is absent and nothing changes for them.
- **The swap is IN PLACE.** [`BattleController._transformInto(id)`](../../src/js/game/BattleController.js) `_cloneState`s the target form and copies its fields onto the SAME `enemyState` object (name/className/portrait/maxHp→full HP/attack/magic/skills/allSkills/relics/aiBehavior, clears statuses & `_defeated`, resets static-modifier bookkeeping) but KEEPS the current `mana`. In-place is REQUIRED because [`PassiveSystem`](../../src/js/systems/PassiveSystem.js) caches the `enemyState` object reference at construction — replacing the object would orphan the dispatcher. It sets the one-shot `enemyTransformed` state (`{ name, portrait, portraitVideo, skills }`); [`BattleScene.updateFromController`](../../src/js/ui/BattleScene.js) calls `setEnemyData(...)` to rebuild the portrait + skills pane (the enemy relic bar + HP/mana re-read from `state.enemyState` every frame, so they need no signal).
- **Phoenix → Egg is `onDeath`; the Egg→win/revert is TURN-BASED + DAMAGE-BASED.** The Phoenix's death-transform uses the **`onDeath`** trigger (TriggerTypes), dispatched from [`_checkGameOver`](../../src/js/game/BattleController.js) via `_tryEnemyDeathTransform` BEFORE victory is declared (re-entry guarded by `_deathTransformFiring`): when the Phoenix HP hits 0 its `sanguine_egg` relic fires `_applyTransform` (become Egg). If after dispatch the enemy is no longer dead, `_checkGameOver` returns false and the battle continues. The revert is driven by the egg-phase turn machinery (below), configured from the `sanguine_egg` relic's `transform` payload; the Egg form's own `sanguine_chrysalis` relic is **DISPLAY-ONLY** (empty `effects` — just an icon + tooltip telling the player to slay the Egg this turn).
- **Phoenix → Egg.** `_applyTransform` swaps into the **dormant but NORMAL, killable** `sanguineEgg` form (NO HP pinning — `_transformInto` already set the Egg to its full floor-scaled HP, baseline 10), STARTS THE EGG PHASE (`_eggPhaseActive=true`, copies `revertEnemyId`/`revertSound` into `_eggPhaseConfig`), and **forces the player to KEEP the turn** by setting `_extraTurnEarned=true` (+ `_eggForcedExtraTurn=true` to suppress the announcement — a "hidden" extra turn). NO egg tiles spawn (the old tile minigame is gone). Re-initialised every time, so a reborn Phoenix can be re-killed into a fresh egg phase.
- **The player KEEPS the turn after the killing blow (no turn pass).** Forcing `_extraTurnEarned` makes EVERY kill path retain the player's turn instead of handing it to the enemy: cascade skull-match kills (via `_finishResolving`'s extra-turn branch), instant skills like **Bash** (`tryPlayerSkill` extra-turn branch), and targeted destroys (`tryTargetTile`). So "kill Phoenix → it becomes a fragile Egg → player keeps playing the same turn to finish it off." `_eggForcedExtraTurn` is consumed (and the log suppressed) at the grant point in each of those three paths; the floating "Extra Turn" image never shows (it's gated on `extraTurnTriggerPos`, set only by real 4+/5+ matches).
- **The win condition is DAMAGE — slay the Egg.** The Egg is a normal enemy: [`_applyDamage`](../../src/js/game/BattleController.js) damages it like anything else (the old `_eggPhaseActive` invulnerability return-0 guard is GONE). When the Egg's HP hits 0 during the retained turn, `_checkGameOver` declares victory via the normal enemy-death path (the Egg has no onDeath transform — `_tryEnemyDeathTransform` returns false); `_checkGameOver` also calls `_endEggPhase()` on a real enemy death so the turn-end deadline can't fire post-victory.
- **Deadline = the player's TURN END** (NOT an egg enemy-turn — the egg never even gets one, since the player keeps the turn and the revert happens before control passes). When the player finally ENDS their retained turn with the Egg still alive, [`_endTurn`](../../src/js/game/BattleController.js) (top, gated `side==='player' && _eggPhaseActive`) calls `_resolveEggPhaseAtTurnEnd()`: the Egg survived → `_transformInto(revertEnemyId)` rebirths a full-life Phoenix IN PLACE (plays `revertSound`); `_endTurn` then proceeds normally so the reborn Phoenix takes the next enemy turn. (A slain Egg already ended the battle in `_checkGameOver` before reaching here — the dead-Egg branch is a defensive guard that just clears the phase.) Because extra turns chain BEFORE `_endTurn` fires, the player gets their full turn (extra turns included) to deal the Egg's HP. `_doEnemyTurn`'s `_isDormantEgg` branch is a safety pass. `_endEggPhase()` clears all phase flags on both slay and revert.
- **No egg tiles.** Eggs no longer spawn — the `SANGUINE_EGG` wild [`TileTypes`](../../src/js/game/TileTypes.js) entry + its `phoenix_egg_tile` art remain registered but are now UNUSED. The deferred-spawn / tile-clear-win machinery (`_pendingEggSpawn` / `_maybeSpawnPendingEggs` / `_eggsSpawned` / `_maybeWinEggPhase` / `_declareEggWin` / `EGG_DISPLAY_HP`) was REMOVED. New skill effect **`gain_max_hp`** (`{ gainMaxHp:{amount} }`, raises maxHp without healing — Blood Gorge) lives in [`MatchResolver` SKILL_EFFECT_TYPES](../../src/js/game/MatchResolver.js) + [`BattleController._resolveEffect`](../../src/js/game/BattleController.js).
- **SFX.** The `sanguine_egg` relic's `transform` payload carries `sound` (death→Egg) + `revertSound` (Egg→Phoenix) surfaced via the one-shot `transformSfx` state (played by BattleScene): `sfx_sanguine_egg_spawn` / `sfx_sanguine_egg_hatch` (the spawn sprite is misspelled `sfx_sanguin_egg_spawn` in the sheet, key stays clean). Skills use `skill_blood_gorge` / `skill_anemic_feast` SFX. All four are sprite-backed in the SFX sheet.
- **Art:** all dedicated and resolved directly from the sheets: portraits `portrait_sanguine_phoenix` + `portrait_sanguine_phoenix_egg`, skill icons `skill_blood_gorge`/`skill_anemic_feast`, relic icons `relic_sanguine_egg` (Phoenix) + `relic_sanguine_chrysalis` (the Egg's display-only relic), egg tile `phoenix_egg_tile` (`tile_sanguine_egg` alias), and the 4 SFX above.
