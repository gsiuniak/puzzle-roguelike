# Decision #40 — Six new weave mechanics — transmute, consume, leech, mark, lock, reflect.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Six new weave mechanics — `transmute`, `consume`, `leech`, `mark`, `lock`, `reflect`.** A batch of Skill Weave tags adding economy / payoff / combo-setup / sustain / control axes the catalog lacked. Each is a [`skillWeaveTags.js`](../../src/js/data/skillWeaveTags.js) entry + a [`weaveConfig.js`](../../src/js/data/weaveConfig.js) `TAG_VALUE_TABLES` magnitude roll + a [`skillSynthesizer.js`](../../src/js/data/skillSynthesizer.js) `emit*` closure wired into the action switch, `emitRandomBonus`, `EFFECT_RESOLUTION_ORDER`, name/suffix/SFX pools, and [`spellIconRecipe.js`](../../src/js/icons/spellIconRecipe.js) (`EFFECT_TAG_PRIORITY` + `EFFECT_SPRITE_ALIAS`, aliased to existing foreground art). The shared grammar trick: a "needs a color" mechanic consumes the woven element in the TARGET slot (via `takeColorType`, so it's not a dangling cost color) — except `consume`, which leaves its color dangling so it still pays the cost.
- **`transmute`** (ACTION, mana economy) → `transmute_mana` effect (`{ transmuteMana:{ color, amount } }`, [`MatchResolver` SKILL_EFFECT_TYPES](../../src/js/game/MatchResolver.js); resolved in [`BattleController._resolveEffect`](../../src/js/game/BattleController.js)). Converts up to `amount` of the caster's OTHER mana into the woven destination color (most-abundant first, finite → no loop), Enfeeble-gated, fires `onGainMana`. A battery for next turn; fixes color screw / funds off-color woven spells. Added to `loopRiskColors` so the affinity fallback never charges in the transmuted color.
- **`consume`** (ACTION, payoff) → `consume` effect (`{ consume:{ resource:'mana'|'armor'|'barrier', color?, divisor } }`). Deals `floor(poolSize / divisor)` damage — **1 damage per `divisor` units, capped at 1-per-2 (½ damage/mana)**, NO stat scaling (the payoff is hoarding a big pool; `divisor` rolls 2/3/4, `greater` sharpens it one step toward the 2 cap). Then SPENDS the pool. The woven `consume` tag emits `resource:'mana'` and binds to a woven color's LEFTOVER mana (the color stays dangling → still pays the cost, so you "over-buy then cash the rest"); no color → all leftover mana. The effect type ALSO supports `armor`/`barrier` so a future Warrior **Shield Bash** skill drops in — NOT added as a starting skill (characters keep exactly 2 skills). Damage routes through `_applyDamage`. (Not `<<n>>`-scalable.)
- **`leech`** (MODIFIER, sustain) → not an effect type; a synthesizer post-pass attaches `damage.leech` (0..1 fraction) to every `damage` effect in the bag. [`BattleController._resolveEffect`](../../src/js/game/BattleController.js) DAMAGE case calls `_applyLeech(src, side, dealt, fraction)` → heals the caster for `floor(dealt × fraction)`. Wasted (downside reason) if the bag has no damage verb.
- **`mark`** (ACTION, combo-setup) → `mark` effect (`{ mark:{ multiplier } }`) arms a one-time damage **MULTIPLIER** (×2, or ×3 with Greater) on `state.mark` (a numeric pool on the combatant, added in `_cloneState`, reset on transform; larger multiplier wins if re-applied). Consumed in the `_applyDamage` chokepoint on the attacker's NEXT damage instance (`dmg = round(dmg × mark)`, applied to raw damage before mitigation; skipped for reflected damage). Persists until consumed — NO timer, so it never depends on Extra Turn. Resolution order 88 (after this skill's own damage), so `mark + strike` in one weave banks for the NEXT hit, not a self-combo.
- **`reflect`** (STATUS, self-buff) → the new **`reflecting`** buff in [`statusEffects.js`](../../src/js/data/statusEffects.js) (icon reuses the now-unused `buff_barrier` crest). While active, the owner **STILL takes the damage but ALSO deals the same amount back** to the attacker: in `_applyDamage`, a target with `reflecting` deals `result.actualDamage` (what just landed) back to the attacker (recursion-guarded by `this._reflecting`). No per-instance value — its only parameter is **duration** (the synthesizer's rolled value = turns, kept short since reflecting ALL damage is strong; priced via `POWER.reflectTurn`). **SFX:** when reflect fires it sets the one-shot `reflectTriggered` state flag → [`BattleScene`](../../src/js/ui/BattleScene.js) plays `sfx_generic_reflect_1` (a clip in the generic SFX sheet).
- **`lock`** (ACTION, board control, **TARGETED**) → `lock_color` effect (`{ lockColor:{ color?, turns } }`). The player **clicks a tile** (the action claims the single targeting slot, `area:{radius:0}`); [`BattleController._executeLockColor`](../../src/js/game/BattleController.js) (dispatched from `tryTargetTile`) locks that tile's color (5 mana colors + skull) for **2–3 turns (2 minimum)**. Lock is **by COLOR** on [`BoardModel`](../../src/js/game/BoardModel.js) (`lockedColors` map + `lockColor`/`isColorLocked`/`tickLocks`, carried through `clone`), NOT per-cell — sidesteps gravity surgery. A locked color is **unmatchable** (skipped in `_scanLineRuns`) and **unmovable** (excluded from `getValidSwaps`; rejected by `tryPlayerSwap`), for BOTH sides — a denial tool. Ticks at each turn start (`board.tickLocks()` in `_completeTurnIntro`), but uses the status-style **`armed`** model: a lock applied mid-turn is ARMED (not decremented) at the very next turn start, so a 1-turn lock covers the OPPONENT's whole turn instead of expiring the instant the turn passes. A NON-targeted fallback path (`_resolveEffect` LOCK_COLOR, used by `random`-granted locks carrying a preset `color`, else `_mostAbundantBoardColor()`) also exists. Has the **`[[Lock]]`** keyword ([`keywordDefinitions.js`](../../src/js/data/keywordDefinitions.js)). Cast/resolve SFX uses the dedicated `sfx_generic_lock_1`/`_2` clips (`pickSkillSound` family `lock`, 2 versions). **`pickSkillSound` now picks the bag's most SALIENT action by `SOUND_PRIORITY`** (not pick-order), so a `lock + armor` spell plays the lock sound rather than gain-armor (lock outranks generic supports; damage outranks lock). Rendered by [`BoardPlaceholder._drawLockedTileOverlay`](../../src/js/ui/BoardPlaceholder.js) — the **`locked_tile`** sprite (in `ui_spritesheet_tiles`, name matches → no alias) drawn over any tile whose color is locked, plus a centered white turns-remaining number badge (`getLockTurns`). **Resolves at order 8 (BEFORE `shuffle` at 10)** so a woven `lock + shuffle` reads the clicked tile's color before the board scrambles (lock is by-color, so the right color stays locked through the shuffle). **Edge cases:** (a) a targeted skill that grants an extra turn WITHOUT a cascade (`lock + extra_turn`) now sets `state = PLAYER_TURN` in `tryTargetTile`'s extra-turn branch — previously it was left stuck in `TARGETING` (the "kept targeting / double-target" bug; cascade-entering targeted skills were unaffected since they route through `_finishResolving`). (b) [`BattleController._maybeAutoPassPlayer`](../../src/js/game/BattleController.js) auto-passes the player's turn when there is no movable tile (all-locked board → empty `getValidSwaps`) AND no castable skill, so a fully-locked board can't soft-lock — called at player turn start (`_completeTurnIntro`) and after a retained (extra) turn.
