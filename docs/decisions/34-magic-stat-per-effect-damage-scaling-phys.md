# Decision #34 — Magic stat + per-effect damage scaling + [[phys]]/[[mag]] damage-type keywords + <<n>> live-value markup.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Magic stat + per-effect damage scaling + `[[phys]]`/`[[mag]]` damage-type keywords + `<<n>>` live-value markup.** Four linked pieces:
- **The Magic stat** mirrors Attack through the three-layer stat architecture (decision #14): `baseStats.startingMagic` (immutable; all 3 characters start at 1) + `statModifiers.startingMagic` (run progression, via `applyRunModifier(runState, 'startingMagic', n)`) → effective `startingMagic` → battle-state field **`magic`** (seeded by [`createPlayerBattleState`](../../src/js/data/playerStats.js), carried through [`BattleController._cloneState`](../../src/js/game/BattleController.js) as `magic: d.magic||0`). Enemies have no `magic` field → 0 (flat). The battle [`CharacterInfoPane`](../../src/js/ui/CharacterInfoPane.js) stat row is **attack | magic | armor** (`icon_magic` sprite).
- **Per-effect scaling** ([`scalingConfig.js`](../../src/js/data/scalingConfig.js), see §4.7). A `damage`, `heal`, OR `armor` effect carries an **individual `scaling: { attack, magic }` object** (each skill/relic tunes its own rate; data references `DAMAGE_SCALE_PER_POINT` = 1/3, or a `DAMAGE_SCALING_PRESETS` value like `._50` = ×1/2, `._33` = ×1/3). The floored owner-stat bonus is added to the flat `amount` in [`EffectResolver`](../../src/js/systems/EffectResolver.js) (`damage`/`heal`/`armor`, relics/passives, `scaledAmount`) and [`BattleController._resolveEffect`](../../src/js/game/BattleController.js) (`damage` alongside `perSkull`, + `heal`/`armor`, via `scaledBonus`). **Defaults:** healing scales off **BOTH Attack and Magic at `_50`** (×1/2 each — Oungan, Alabaster Flask, Soul Eater, woven Heal); armor gain scales with **Attack at `_33`** (Defend, Aegis, woven Armor). The bonus uses the OWNER's stats, so the same field serves players + enemies; gating is purely "does this effect carry `scaling`". Today: **Bash** (`{magic}`); relics **Trebuchet + 5 mana-reactor arrows** (`{magic}`), **Slingshot + Thorned Rose** (`{attack}`). **Enemy damage/armor skills also scale** (`{attack}`, default `_50` damage / `_33` armor: Slash, Boulder Throw, Smash, Charge, Infected Bite, Hound, Frenzy; `boom_baby` stays flat) — combined with the per-floor enemy-attack bonus (decision #11) this makes later enemies burst harder. **Woven skills now scale too** — the Skill Weave's `strike`/`blast` damage tags roll a scaling multiplier preset and emit `<<n>> [[phys]]/[[mag]]` descriptions (see decision #35).
- **Damage-type keywords `[[phys]]`/`[[mag]]`** ([`keywordDefinitions.js`](../../src/js/data/keywordDefinitions.js): labels "Physical Damage"/"Magic Damage") REPLACE `[[damage]]` in scaled descriptions ("Deal <<1>> [[mag]]…") — the keyword's own tooltip is self-contained ("scales with [[Attack]]/[[Magic]]"), so there is NO separate "Scales with…" line. (`[[Magic]]` is also a stat keyword.)
- **`<<n>>` dynamic-value markup** — a sibling of `[[keyword]]` parsed by [`keywordParser.js`](../../src/js/systems/keywordParser.js) (`type:'dynamic'`) and rendered by [`KeywordText`](../../src/js/ui/KeywordText.js) in `KEYWORD_DYNAMIC_COLOR` (green). It shows the ACTUAL computed amount, not a static number. `scalingConfig.resolveDynamicText(raw, effects, caster)` pairs each `<<n>>` (in order) with a scalable effect — **damage, heal, or armor** (via `scalablePayload`) — and rewrites it to `amount + bonus`. Wired LIVE: [`skillCard.js`](../../src/js/ui/skillCard.js) `measureCardModel` re-resolves every frame from the card's `caster` (the pane's combatant — [`SkillsPane.setOwnerStats`](../../src/js/ui/SkillsPane.js) / [`SkillLoadoutOverlay.show({caster})`](../../src/js/ui/SkillLoadoutOverlay.js), fed by BattleScene); [`RelicBar.setOwnerStats`](../../src/js/ui/RelicBar.js) bakes the resolved value into each relic tooltip (re-attaches on stat change); [`RewardOptionPanel.setRelic(def, ownerStats)`](../../src/js/ui/RewardOptionPanel.js) resolves it on the reward cards (BattleScene passes the player's current effective stats via `RewardOverlay.prepareRewards(defs, ownerStats)`) so a reward shows its REAL stat-scaled damage, not the base. No caster → base amount.
- **To make an effect scale:** add `scaling: { magic: DAMAGE_SCALE_PER_POINT }` (or `{attack}`) to its `damage` payload and write the description as `Deal <<N>> [[mag]]` (or `[[phys]]`). **To retune the global rate:** edit `DAMAGE_SCALE_PER_POINT`.
