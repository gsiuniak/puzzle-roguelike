# Decision #43 — BattleController rework (2026-07): one cast pipeline, an effect-handler registry, and simulation-based board AI.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**BattleController rework (2026-07): one cast pipeline, an effect-handler registry, and simulation-based board AI.** Implements the top items of [`docs/reviews/battlescene-battlecontroller-architecture-review.md`](../reviews/battlescene-battlecontroller-architecture-review.md) (R1/R2/R10-lite/R11/R12/R14/R15) plus the new AI layer. Full implementation record (incl. latent bugs fixed + deliberate behavior changes): [`docs/reviews/battlecontroller-rework-2026-07.md`](../reviews/battlecontroller-rework-2026-07.md). **Before amending BattleController, load the `battlecontroller` skill** ([`.claude/skills/battlecontroller/SKILL.md`](../../.claude/skills/battlecontroller/SKILL.md)) — invariants + recipes + headless verification harness.
- **R1 — single skill-cast pipeline.** The four divergent skill-execution paths (player instant / player targeted / enemy standard-AI / enemy custom-AI) are gone: all route through `_castSkill(side, skill, {targetCol?, targetRow?, targetArea?})`. Targeting-aware board effects (destroy/convert/lock) consume the passed area via `_dispatchTargetedEffect`; everything else goes through the registry. The shared epilogue `_finishInstantAction(side)` owns game-over check → pending skull-destroy drain → extra-turn routing (player: leave TARGETING + egg-suppression + auto-pass check; enemy: re-arm `_enemyFired`/`_enemyTimer`) → `_endTurn`. The historical "kept targeting" and "enemy freeze" bug classes are structurally impossible now. `_beginEnemyExtraTurn` was absorbed; `_doEnemySwap` + the custom-AI swap branch share `_performEnemySwap(swap)`. Two side-effect fixes: enemy non-cascade casts now drain pending skull destroys too (they previously leaked to the player's next action), and `_executeDestroyTiles` no longer hardcodes `activeSide='player'` (enemy destroy-type skills credit the enemy).
- **R10-lite — action-scoped extra-turn flag.** `_beginResolving` no longer resets `_extraTurnEarned`; see decision #4 (the create_tiles/extra_turn authoring order trap is retired).
- **R2 — effect-handler registry.** `_resolveEffect`'s 23-case switch moved to [`battle/skillEffectHandlers.js`](../../src/js/game/battle/skillEffectHandlers.js) (see its §4.3 row). Armor/barrier/heal/gain_attack/gain_magic delegate to `EffectResolver.applyEffect` — single implementation for the skill AND relic paths.
- **R11 — transform derives from the clone spec.** `_transformInto` copies every field of a fresh `_cloneState(form)` onto the live enemyState (keeping only `mana`, then hp=maxHp + bookkeeping resets) — a new battle-state field added to `_cloneState` flows to transforms automatically. (Behavior note: `poison` now resets on transform like the other runtime pools — "fresh body" semantics.)
- **R12/R14/R15** — `_setState(next)` is the single transition point (always fires `onStateChange`); dead `screenToBoard`/`enterTargeting` deleted; `opponentOf(side)`/`posKey(p)` utils; named constants `STATUS_DAMAGE_MODS`, `POISON_DECAY_DIVISOR`, `SHAKE_FULL_AT_HP_FRACTION`, `MARK_DEFAULT_MULT`, `LOCK_MIN_TURNS`.
- **Board AI layer (NEW).** [`BoardSimulator.js`](../../src/js/game/BoardSimulator.js) — pure headless cascade prediction (guaranteed deterministic outcome + Monte-Carlo refill expectation) on board clones; [`MoveAdvisor.js`](../../src/js/game/MoveAdvisor.js) — general side-agnostic move ranking (mana-toward-skills, denial, skull damage/lethal, extra-turn odds, cascade depth, 1-ply opponent-reply lookahead; `DEFAULT_WEIGHTS` = the tunable personality). Exposed but deliberately UNWIRED: enemies opt in per-def via `aiBehavior: 'smart_matcher'` (no enemy uses it yet — skill choice stays with the standard AI, only the swap decision upgrades); player hints via `BattleController.getSuggestedMove()`/`getRankedMoves()` (SUPERSEDED for the hint UI 2026-07-08 by the champion-policy `getSuggestedAction()` — see decision #45; MoveAdvisor remains the smart_matcher engine). Both are on-demand computations (hundreds of board sims per call) — never call per frame.
