# Decision #41 — Damage feedback is an accumulating per-side COUNTER (not per-hit text); mana matches fly whispy streams to the mana orbs.

> Extracted verbatim from CLAUDE.md §7 (2026-07-14 split). Historical record — reflects the design at time of writing.

**Damage feedback is an accumulating per-side COUNTER (not per-hit text); mana matches fly whispy streams to the mana orbs.** Replaces the old per-instance floating "-x" damage text with two coordinated juice systems, both BattleScene-side (no battle-logic changes beyond augmenting `matchTextTriggers`):
- **Damage counter** ([`DamageCounterEffect`](../../src/js/ui/DamageCounterEffect.js)). DAMAGE `floatingStatEvents` (kind `'damage'`, from the single `_applyDamage` chokepoint) route to [`BattleScene._addDamageToCounter(side, amount, maxHp)`](../../src/js/ui/BattleScene.js) instead of `_spawnStatTextEffect`. One stylized counter per side appears centered in the RECEIVING side's info column (the name/class/stats column — player pane left, enemy pane right) and ACCUMULATES every hit in a sequence (3 → cascade +5 → shows 8), showing the running total + a CHAIN count (`34 DAMAGE` / `CHAIN x3`). It intensifies with RELATIVE damage (`total / (maxHp * INTENSITY_FULL_FRACTION)`): a gold→orange→red color ramp, larger font, stronger additive glow. Each hit replays a punchy tick — scale "punch" + rotational wobble (`PUNCH_*`), positional shake (`SHAKE_AMP`), glow flare (`FLARE_GLOW`), slash accents. **Finalize = end of the damage sequence:** the counter holds open while the board is resolving (BattleScene feeds `counter.resolving = (state RESOLVING/SWAPPING) && activeSide !== side` each frame, so a whole cascade stays ONE counter and finalizes promptly once it's the receiver's own turn); when no new damage arrives for `FINALIZE_IDLE_MS` while not resolving, it FINALIZES (number grows with a bounce, "DAMAGE"+chain fade out), then the bare number FLIES in an arc to the receiver's portrait (`setTarget`) shrinking, and IMPACTS with a flash + spark burst that fires `onImpact(intensity)` (LEFT UNWIRED by BattleScene — the impact deliberately triggers no extra screen shake; the flash/sparks are the whole punch). NOTE: actual HP/damage is applied earlier in battle logic (immediate) — the fly-to-portrait is purely ceremonial delivery, not a deferred damage application. BattleScene feeds the per-side anchor (`_getDamageCounterAnchor(side)` — the receiver pane's `getInfoColumnRect()` center; health-bar fallback lifted `DAMAGE_COUNTER_BAR_LIFT` px until laid out) via `setCenter` + the portrait (`setTarget`) anchors each frame. **Turn gating (two-phase TURN_INTRO):** so the damage fully delivers BEFORE the next turn is announced/acted, [`_endTurn`](../../src/js/game/BattleController.js) defers the turn announcement. TURN_INTRO now runs **Phase A** (silent hold — no "Player/Enemy Turn" popup — while a just-dealt damage counter flies to + impacts the target portrait) then **Phase B** ([`_beginTurnAnnouncement`](../../src/js/game/BattleController.js) raises `_turnAnnouncement` → the scene spawns the popup, then the normal `TURN_INTRO_DURATION` delay → `_completeTurnIntro` → the turn acts). The hold is driven by the scene-supplied gate [`BattleController.setTurnGate`](../../src/js/game/BattleController.js) → `BattleScene._hasPendingDamageDelivery()` (true while any counter is not `done` and not `delivered` — the counter's `delivered` getter flips true once impact fires); capped by `TURN_GATE_MAX_HOLD` (2000ms) so a stuck effect can't freeze the battle, and `_introAnnounced` starts true so the first turn (no damage pending) announces immediately. Extra turns bypass TURN_INTRO entirely, so they aren't gated (no turn passes). Managed per side in `BattleScene._damageCounters` (kept in `_floatingEffects`); a finalizing/done counter is replaced by a fresh one on the next hit. The other stat kinds (heal/armor/barrier/poison) still float as independent `FloatingTextEffect`s. All feel tunables are top-of-file consts in the effect; the number/label glyphs are authored sprites from `ui_spritesheet_combat_damage` (label `ui_animated_text_damage_chain_single_digit`/`_double_digit` chosen by chain digit count + `digit_0`…`digit_9`), fetched from the AssetManager (passed into the effect ctor).
- **Mana streams** ([`ManaStreamEffect`](../../src/js/ui/ManaStreamEffect.js)). `matchTextTriggers` now carries every matched cell (`positions`, added in [`BattleController`](../../src/js/game/BattleController.js)). For each mana-color match (skull/inert excluded via `isMana`), [`BattleScene._spawnManaStream(trigger, activeSide)`](../../src/js/ui/BattleScene.js) flies a few thin glowing color-tinted wisps from the matched cells to the matching mana orb in the side that GAINED the mana (the active side; orb position via [`CharacterInfoPane.getManaOrbCenter(color)`](../../src/js/ui/CharacterInfoPane.js)). As the leading wisps land, the effect's `onArrive` callback pulses the orb ([`CharacterInfoPane.pulseManaOrb`](../../src/js/ui/CharacterInfoPane.js) → [`UIOrb.pulse()`](../../src/js/ui/UIOrb.js)): a slight, NON-intensifying scale bobble (`UIOrb.PULSE_*`, decayed in `update(dt)`, applied as a center-scale transform in `renderSelf`). The "+N" board match text is unchanged (still spawned alongside).
